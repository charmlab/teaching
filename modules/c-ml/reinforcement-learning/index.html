Reinforcement Learning

Every algorithm in this course so far learned from information someone handed it. Supervised learning got labels: here is the input, here is the right answer, match them. Unsupervised learning got structure to find: here is the data, uncover its patterns. This final lecture removes both crutches. The agent gets no labels and no correct answers, only a number that arrives after it acts, sometimes long after: a reward. From that thin signal it must learn what to do. That setting covers slot machines, self-driving cars, and the chess engines that beat us at our own game, and it runs on three ideas: exploration, the Markov decision process, and one recursive equation that Richard Bellman wrote down in the 1950s. By the end you will train an agent yourself and watch knowledge flow backward from the goal.

0. The hook: no labels, no answers, just reward

Line up the three kinds of learning this course has met. Supervised learning matches labels: a spam filter sees emails already marked spam or not, and imitates the marking. Unsupervised learning uncovers patterns: customer segmentation finds groups nobody labelled. Reinforcement learning, the third family, maximizes reward: a chess AI plays, and much later a single number comes back, win or lose. Nobody tells it which move was the mistake.

That last sentence is the entire difficulty, so read it again. Rewards are feedback from the world, not ground-truth targets. The agent receives a stream of inputs, acts, and its actions change the state of the world; occasionally a reward or penalty arrives. When the game is lost on move sixty, which of the sixty moves was wrong? There is no label to say. And yet this setting produced some of the most famous results in the field: Richard Sutton, who pioneered the theory, won the 2025 Turing Award for it, and Demis Hassabis, whose DeepMind built AlphaGo on these ideas, is a 2024 Nobel Laureate. So the thin signal is enough. Watch it be enough:

Fig 0.1, where this lesson ends up: an agent learning to act from reward alone. Press Train and a real Q-learning agent (the algorithm of section 5, running live) explores the grid, finds the goal, and builds value estimates, shown as the deepening colour, and a policy, shown as the arrows, from nothing but a reward at the goal. Early episodes wander for dozens of steps; later ones walk straight in. Nobody labelled a single move.

Everything that just happened on that grid needs explaining. Why did the agent ever try a bad direction? That is exploration, and section 1 isolates it with the simplest possible problem, a row of slot machines. What did the colours mean? Those are value functions, section 3. Why did the colour spread backward from the goal? That is the Bellman equation doing its work, sections 4 and 5. The lecture's spine, and this lesson's, is exactly that ladder: bandits introduce exploration, MDPs add state and delayed consequences, and Bellman equations turn long-term value into a one-step recursion that we either plan with, when the world's rules are known, or learn, when they are not.

1. Bandits: learning what pays

A casino with unknown machines

Strip away everything except the core problem. You walk into a casino with a row of $K$ slot machines. Each machine pays out a random reward from its own distribution, and you do not know any of the distributions. You can play as many rounds as you like, one machine per round, and you observe only the payout of the machine you played. Your goal: maximize total reward. This is the multi-armed bandit problem, named for the slot machine's nickname, the one-armed bandit.

Formally, at each round $t$ the agent selects an action $a_t \in A$ (which machine to play) and receives a stochastic reward $r_{t+1}$. Each action has an unknown true value, the expected reward for playing it:

$$ q_*(a) := \mathbb{E}[r_{t+1} \mid a_t = a], \qquad r_{t+1} \sim p(\cdot \mid a_t), $$

and the objective is to maximize expected cumulative reward, $\max \, \mathbb{E}\!\left[\sum_{t=0}^{T-1} r_{t+1}\right]$. If someone told us $q_*(a)$ for every machine we would play the best one forever and be done. Nobody tells us, so we estimate it the obvious way, by the sample average of the rewards each action has produced:

$$ Q_t(a) = \frac{\sum_{i=1}^{N_t(a)} r_i(a)}{N_t(a)}, $$

where $N_t(a)$ counts how many times action $a$ has been played so far. Play machine 3 three times, see payouts 1, 0, 1, and your estimate is $Q_t(3) = 2/3 \approx 0.667$. Simple. So are we done? Just play a bit, then commit to the machine with the best average?

The exploration-exploitation dilemma

No, and here is the trap: a high empirical average from a few plays is not conclusive. A mediocre machine can get lucky twice; a great machine can start cold. Rarely sampled actions have uncertain estimates, and the only way to shrink the uncertainty is to play them, which costs you rounds on the machine you currently believe is best. Every round forces a choice between two motives:

  • Exploitation: play $a_t = \arg\max_a Q_t(a)$, the best machine according to current knowledge. Uses what you know; risks committing too early to a lucky impostor.
  • Exploration: play a less familiar machine to improve an uncertain estimate. Buys information; costs immediate reward.

This tension is everywhere once you see it. Your favourite restaurant or the new one? Drill the oil site you know pays or survey a new spot? Play the chess move you trust or the experimental one? Show the ad with the best click-through rate or a different one? Test yourself on the trade-off, then feel it directly on a live bandit:

Two standard strategies

$\epsilon$-greedy is the blunt fix: with probability $1 - \epsilon$ exploit, $a_t = \arg\max_a Q_t(a)$, and with probability $\epsilon$ pick an action uniformly at random. It is simple and it works, but notice what it ignores: when it explores, it explores blindly, paying no attention to which actions are actually uncertain. A machine played once and a machine played a hundred times get the same share of the random picks. In practice $\epsilon$ often decays during learning, exploring heavily early and settling down later.

Upper Confidence Bound (UCB) explores with intent. Score each action by its estimate plus a bonus that grows with uncertainty:

$$ a_t = \arg\max_a \left[ Q_t(a) + c\sqrt{\frac{\log t}{N_t(a)}} \right]. $$

Read the bonus term: $N_t(a)$ in the denominator makes it large for under-sampled actions and small for well-sampled ones, while the slow-growing $\log t$ in the numerator keeps a little pressure on everything as time passes. UCB is optimism in the face of uncertainty: it plays the action whose plausible best case is highest, so uncertain actions get tried precisely because they might be great, and each trial shrinks their bonus. One practical note: initialize by playing every action once, so every $N_t(a) > 0$ before the formula takes over. Now play the real thing:

Each bar is the live sample average $Q_t(a)$ with its count $N_t(a)$, the purple whisker is UCB's exploration bonus $c\sqrt{\log t / N_t(a)}$, and every payout is a genuine random draw. import numpy as np

def ucb_select(Q, N, t, c):
    # Q: sample-average estimates, N: play counts, t: current round
    # play any unplayed arm first so N > 0 everywhere
    if np.any(N == 0):
        return int(np.argmin(N))
    bonus = c * np.sqrt(np.log(t) / N)
    return int(np.argmax(Q + bonus))

Q = np.array([0.7, 0.3, 0.6])
N = np.array([6, 1, 2])
ucb_select(Q, N, t=9, c=1.0)   # -> 1 (arm 2: biggest bonus wins)

Check: why can't we conclude the highest-average arm is best?

Arm 1 has the highest sample average after nine plays. Why is committing to it forever a mistake?

Answer. Because $Q_t(a)$ is an estimate of $q_*(a)$, and its reliability depends on $N_t(a)$. Arm 2's average rests on a single random draw; one unlucky payout put it at 0.3, and no future play will ever correct that if we go greedy, since greedy never plays it again. This is the exploration-exploitation dilemma in one sentence: the data you collect depends on the actions you take, so acting only on current estimates can lock in early noise. Both fixes in this section are ways of refusing to let that happen, blindly ($\epsilon$-greedy) or with intent (UCB).

2. From bandits to states

The bandit taught us exploration, but look at what it lacks. Whatever machine you play, the casino is unchanged next round: same machines, same odds. In the bandit, the reward depends only on the action, $r_{t+1} \sim p(\cdot \mid a_t)$, and an action affects the current reward but not the next decision. Almost nothing interesting is like that. In chess, a move changes the board you face next. In driving, an acceleration changes the situation you must handle next. Actions have consequences, and consequences are exactly what the bandit throws away. Climb the ladder one rung at a time:

Fig 2.1, the bandit-to-MDP ladder. Switch between the three settings and watch what the reward is allowed to depend on: action only (bandit), state and action (contextual bandit), and state and action with the action also producing the next state (MDP), which closes the loop and makes decisions sequential. Press Pulse (or Step) to animate one round through each diagram.

The middle rung, the contextual bandit, lets the reward depend on a state as well as the action, $r_{t+1} \sim p(\cdot \mid s_t, a_t)$: which ad works depends on which user is looking. But the state still arrives from outside; your action does not shape it. The top rung is the full Markov decision process, where the action also affects the next state:

$$ (r_{t+1}, s_{t+1}) \sim p(\cdot, \cdot \mid s_t, a_t). $$

That one addition changes everything, because now a decision's consequences ripple forward. The interaction becomes a loop: at each step, the agent in state $s_t$ takes action $a_t$, receives reward $r_{t+1}$, and moves to state $s_{t+1}$. This loop is the spine of everything that follows, so watch it run:

Fig 2.2, the agent-environment loop, animated on a real environment. The agent sends an action; the environment answers with a reward and the next state; repeat. Step it and the trajectory log fills with an actual $s_t, a_t, r_{t+1}, s_{t+1}$ sequence from the gridworld used throughout this lesson, one genuine transition per press.

A sequential decision problem, viewed through this loop, has three parts, and the vocabulary is worth fixing now. A policy is the agent's behaviour, its rule for choosing actions from states. A value function evaluates situations: how good is this state, given how I will act from here on? A model is the environment's side of the loop: how the world responds to actions. Section 3 makes each precise.

Check: where exactly did "state" enter, and what did it cost us?

Between the bandit and the MDP, what structurally changed, and why does it make learning harder?

Answer. Two insertions. First, the reward became conditional on a state as well as an action (the contextual rung): the right choice now varies with the situation, so instead of one best action we need a best action per state, a policy. Second, the action began producing the next state (the MDP rung): consequences became sequential. The cost is delayed consequences: a bad action might pay well now and ruin the states we reach later, so judging an action by its immediate reward, which was the entire bandit game, is no longer valid. We will need a quantity that folds the future back into the present. That quantity is the value function, and building it is the next section's whole job.

3. MDPs, policies, and value functions

Policies: deterministic and stochastic

A policy $\pi : S \to A$ selects actions from states. It can be deterministic, $a_t = \pi(s_t)$, always the same action in the same state, like a train following fixed signals. Or it can be stochastic, $a_t \sim \pi(a \mid s)$, a probability distribution over actions, like a recommender system that deliberately adds diversity rather than always serving the single top item. The optimal policy is the one that maximizes total reward. But "total reward" hides a problem: over an unbounded future, $\sum_k r_{t+k}$ may be infinite, and comparing infinities gets us nowhere. The fix is to discount:

$$ \arg\max_\pi \; \mathbb{E}\big[r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + \cdots\big], \qquad 0 \le \gamma < 1. $$

The discount factor $\gamma$ does three jobs at once. It makes the sum converge, since $\gamma^k$ shrinks geometrically. It sets the effective planning horizon: small $\gamma$ makes the agent near-sighted, caring mostly about immediate rewards, while $\gamma$ near 1 makes it far-sighted, weighing long-term consequences almost fully. And it lets the agent balance immediate against future reward with a single dial. Turn that dial:

Fig 3.1, the discount factor as a planning horizon. The bars are the weights $\gamma^k$ on rewards $k$ steps ahead, recomputed as you slide $\gamma$; the readouts evaluate two concrete reward streams live: a steady +1 per step, whose return approaches $1/(1-\gamma)$, and a single +10 arriving three steps from now, worth $10\gamma^3$ today. At $\gamma = 0.9$ those are 10 and 7.29; drop to $\gamma = 0.5$ and patience stops paying.

Value functions: folding the future into the present

With the discounted return defined, we can say precisely how good a situation is. Value functions predict expected discounted future reward:

$$ V^\pi(s) := \mathbb{E}\!\left[\sum_{k=0}^{\infty} \gamma^k r_{t+k+1} \,\Big|\, s_t = s, \pi\right], \qquad Q^\pi(s, a) := \mathbb{E}\!\left[\sum_{k=0}^{\infty} \gamma^k r_{t+k+1} \,\Big|\, s_t = s, a_t = a, \pi\right]. $$

$V^\pi(s)$, the state-value, answers "how much reward should I expect from state $s$ onward, if I follow policy $\pi$?". $Q^\pi(s, a)$, the action-value, answers the finer question "and what if I first take action $a$, then follow $\pi$?". Note the family resemblance to the bandit's $Q_t(a)$: same letter, same meaning, expected return of an action, but now indexed by state, because in an MDP the same action can be brilliant in one state and fatal in another.

Why does the agent need this machinery at all? Picture a maze: the states are the agent's location, the actions are $\{N, E, S, W\}$, and the rewards are $-1$ per step, $-1$ for bumping a wall, and $+100$, plus termination, for reaching the goal. The agent observes only its current square and applies its policy locally; it cannot see the goal from where it stands. Local decisions, global objective. The value function is precisely the device that informs local choices of their global consequences: if each square's value already summarizes the discounted future from that square, then steering uphill in value is globally correct while looking only one step ahead.

The MDP, formally, and the Markov property

A Markov decision process packages the whole setting into a 5-tuple $\langle S, A, P, R, \gamma \rangle$:

  • $S$: the set of states; $A$: the set of actions.
  • $P(s' \mid s, a)$: the transition model, the probability of landing in $s'$ after taking $a$ in $s$.
  • $R(s, a, s')$: the reward for the transition $s \xrightarrow{a} s'$.
  • $\gamma \in [0, 1)$: the discount factor.

The name carries an assumption, the Markov property: the current state summarizes all past information needed to predict the next,

$$ P(s_{t+1} \mid s_0, a_0, \dots, s_t, a_t) = P(s_{t+1} \mid s_t, a_t). $$

You have met this move before. The n-gram models of the language-modeling lecture made exactly this bet: recent context replaces full history, and predicting the next word needs only the last few. Here, predicting the next state needs only the current state and action, not the whole trajectory that led there. It is a modelling choice, and it is what will let us write value recursively in section 4: if the state is a sufficient summary, then value can be computed state by state instead of trajectory by trajectory.

Make the 5-tuple concrete with the lecture's car. States: the engine is Cool, Warm, or Overheated. Actions: drive Slow or Fast. Going fast pays double, $+2$ against $+1$, while the engine holds, but fast driving heats the engine, and from Warm it is certain doom: the engine overheats and the drive ends with a $-10$ penalty. Planning versus learning

One fork in the road decides the rest of this lesson. If we possess the complete MDP, all five pieces including $P$ and $R$, then nothing is unknown about how the world works, and finding the optimal policy is pure computation. We plan, with model-based methods: value iteration and policy iteration, section 4. If we lack full knowledge of $P$ and/or $R$, the real reinforcement-learning setting, then the agent must learn from interaction, with model-free methods: Q-learning (and its relative SARSA), section 5.

4. Planning: Bellman equations, value and policy iteration

The one-step trick

Suppose we know the full MDP. How do we actually compute $V^\pi$, an expectation over infinitely long futures? Reasoning over whole trajectories is hopeless; the number of paths explodes. Richard Bellman's insight, the foundation of dynamic programming, is that the Markov property lets us cut the infinite sum after one step. Write the return recursively:

$$ G_t = r_{t+1} + \gamma G_{t+1}. $$

The return from now is the immediate reward plus the discounted return from next step onward, and thanks to the Markov property "from next step onward" depends only on where you land. Take expectations and the value function inherits the same shape, the Bellman equations:

$$ V^\pi(s) = \sum_{a \in A} \pi(a \mid s) \sum_{s' \in S} P(s' \mid s, a)\big[R(s, a, s') + \gamma V^\pi(s')\big], $$ $$ V_*(s) := \max_\pi V^\pi(s) = \max_{a \in A} \sum_{s' \in S} P(s' \mid s, a)\big[R(s, a, s') + \gamma V_*(s')\big]. $$

Read the first one aloud: under a fixed policy, a state's value is the expected immediate reward plus the discounted value of wherever you land. The second, the Bellman optimality equation, replaces the policy's average over actions with a max: the best value of a state is achieved by taking the best action. (Notation: $V_*$ and $Q_*$ abbreviate $V^{\pi_*}$ and $Q^{\pi_*}$, the values of the optimal policy.) An infinite-horizon problem just became a local consistency condition between each state and its neighbours. Everything else in this lesson is a way of solving that condition.

Value iteration

The optimality equation defines $V_*$ implicitly, as the values that are consistent with themselves. Value Iteration (VI) solves it by brute repetition: initialize $V_0(s)$ arbitrarily, say all zeros, then repeatedly apply the right-hand side as an update to every state:

$$ V_{k+1}(s) = \max_a \sum_{s'} P(s' \mid s, a)\big[R(s, a, s') + \gamma V_k(s')\big], $$

sweeping until the biggest change in any state is tiny, $\lVert V_{k+1} - V_k \rVert_\infty \le \epsilon$, then extracting the policy by acting greedily on the converged values, $\pi_*(s) = \arg\max_a \sum_{s'} P(s' \mid s, a)[R(s, a, s') + \gamma V_*(s')]$. Why does hammering the same update work? Because each sweep propagates long-term consequences one step backward. After one sweep, states adjacent to reward know about it. After two, their neighbours do. Information radiates outward from wherever reward lives. Watch it radiate:

Policy iteration, and the comparison

Value iteration never writes a policy down until the very end. Policy Iteration (PI) takes the opposite route: keep an explicit policy at all times, and alternate two moves. Start from a random policy $\pi_0$, then repeat:

  • Policy evaluation: compute this policy's value by sweeping its own Bellman equation (no max, the policy chooses the action): $V_{k+1}(s) = \sum_{s'} P(s' \mid s, \pi_k(s))\big[R(s, \pi_k(s), s') + \gamma V_k(s')\big]$.
  • Policy improvement: act greedily against those values to get a better policy: $\pi_{k+1}(s) = \arg\max_a \sum_{s'} P(s' \mid s, a)\big[R(s, a, s') + \gamma V_{k+1}(s')\big]$.

So VI directly computes optimal values via the Bellman optimality equation and extracts a policy once at the end: many cheap iterations, no explicit intermediate policies. PI alternates evaluating and improving an explicit policy: fewer outer iterations, but each one contains a full evaluation, which is itself many sweeps. Both lean on the same Bellman machinery, both are guaranteed to converge to the optimal policy, and on the same problem they deliver similar policies. Race them:

Fig 4.3, value iteration and policy iteration racing on the same maze. Left: VI updates values every step and only implies a policy. Right: PI starts from a deliberately bad fixed policy, fully evaluates it (inner sweeps counted), improves, and repeats. The counters tally each method's work live: VI takes more, cheaper steps; PI takes fewer, costlier ones; and the finish line is the same optimal policy, arrow for arrow.

The code is short enough to read in one breath, and it runs for real below: 

import numpy as np

def value_iteration(P, R, gamma, eps=1e-6):
    # P[s][a] -> list of (prob, s_next); R[s][a][s_next] -> reward
    V = np.zeros(len(P))
    while True:
        V_new = np.array([
            max(sum(p * (R[s][a][s2] + gamma * V[s2]) for p, s2 in P[s][a])
                for a in range(len(P[s])))
            for s in range(len(P))
        ])
        if np.max(np.abs(V_new - V)) <= eps:      # ||V_{k+1} - V_k||_inf
            break
        V = V_new
    policy = [int(np.argmax([sum(p * (R[s][a][s2] + gamma * V[s2])
                                 for p, s2 in P[s][a])
                             for a in range(len(P[s]))]))
              for s in range(len(P))]
    return V, policy

Check: how do value iteration and policy iteration actually differ?

Both converge to the optimal policy on this maze. What is each one doing differently along the way?

Answer. VI iterates on values: it applies the Bellman optimality backup (with its max over actions) to every state, over and over, and no policy exists until the final greedy extraction. Each iteration is cheap, one backup per state, but many iterations may be needed for values to converge. PI iterates on policies: it holds a concrete policy, computes that policy's exact value by sweeping the Bellman expectation equation (no max, the policy has already chosen), then improves the policy greedily. Its outer loop typically converges in very few rounds, but each round hides a full evaluation, which is many sweeps of work. Same Bellman core, two schedules: continuous small corrections versus deliberate evaluate-then-improve strokes. Fig 4.3's counters make the trade concrete, and both finish at the same arrows.

5. Learning: Q-learning

Losing the model, keeping the recursion

Now delete the map. Suppose $P$ and $R$ are unknown: the agent can act and observe, but it cannot look up what any action will do. Value iteration is dead on arrival, its update sums over transitions we cannot enumerate. What survives? Here is the elegant move: learn action values directly. Define, for the deterministic world where taking $a$ in $s$ leads to the (unknown) state $\delta(s, a)$:

$$ Q_*(s, a) = r(s, a) + \gamma V_*(\delta(s, a)). $$

Why is this the right object? Because if we somehow possessed $Q_*$, acting optimally would need no model at all: $\pi_*(s) = \arg\max_a Q_*(s, a)$, just compare the entries for the current state and take the best. The model got baked into the table. And since $V_*(s) = \max_a Q_*(s, a)$, substituting gives $Q_*$ its own self-referential Bellman equation, with no $V$ and no $P$ in sight:

$$ Q_*(s_t, a_t) = r(s_t, a_t) + \gamma \max_{a'} Q_*(s_{t+1}, a'). $$

Everything on the right is observable in a single step of experience: take the action, receive $r$, see where you land, look up your own table there. That observation becomes the Q-learning training rule. Keep an estimate $\hat{Q}$, and after each transition, overwrite one entry with what the experience says it should be:

$$ \hat{Q}(s, a) \leftarrow r(s, a) + \gamma \max_{a'} \hat{Q}(s', a'), $$

where $s'$ is the state actually reached. The full algorithm is barely longer: initialize every $\hat{Q}(s, a) = 0$; from an initial state, repeatedly select and execute an action, receive $r$, observe $s'$, apply the update, set $s \leftarrow s'$; when an absorbing state is reached, restart the episode. Each step changes only the single entry $\hat{Q}(s, a)$, and with non-negative rewards the estimates only rise from 0 toward the true $Q$.

Worked by hand: one Q-learning update

The lecture's grid: rewards are 0 everywhere except entering the goal, $\gamma = 0.9$. From state $s_1$ the agent moves right into $s_2$, receiving $r = 0$. The entries already stored for $s_2$'s three actions are 63, 81, and 100. The rule overwrites one number:

Q̂(s₁, aright) ← r + 0.9 · max{63, 81, 100} = 0 + 0.9 · 100 = 90

Nothing else in the table moves. Notice what the update did: it pulled the goal's value one state further from the goal, discounted once. That is the same backward radiation as value iteration, except it happens only along the path the agent actually walked.

Watching knowledge propagate backward

That last observation deserves to be seen, because it explains why early training looks so useless. All entries start at 0, and rewards are 0 until the goal, so during the entire first episode every update writes $0 + \gamma \max\{0, \dots\} = 0$. Nothing happens. Only the very last transition of episode one, the step into the goal, writes something: the goal reward. In the next episode, information reaches one step further back: the transition into that state now sees a non-zero $\max_{a'} \hat{Q}$ and captures its discount. Episode by episode, non-zero values crawl backward from the goal until reward information fills the state-action space. Train it and watch:

Exploration, again, and a familiar face

How should the agent pick actions while it learns? Acting greedily on $\hat{Q}$ is risky for exactly the bandit reason: an early accident writes a mediocre value, greed never revisits, and the error freezes. The lecture's fix is a stochastic policy that prefers good-looking actions without ever fully abandoning the rest:

$$ P(a_i \mid s) = \frac{\exp\big(k\,\hat{Q}(s, a_i)\big)}{\sum_j \exp\big(k\,\hat{Q}(s, a_j)\big)}. $$

Look familiar? It should: this is the softmax, the same normalized exponential that turned scores into class probabilities in logistic regression and into soft cluster responsibilities in soft K-means. Here it turns Q-values into action probabilities, and the constant $k$ plays the sharpening role: small $k$ flattens the distribution toward uniform, pure exploration, while large $k$ spikes it onto the argmax, pure exploitation. Vary $k$ over time, small early and large late, and you get the same anneal-from-exploration schedule as a decaying $\epsilon$, but graded by quality: second-best actions keep more probability than terrible ones.

When the world is random: slow down the pen

One last upgrade. In a non-deterministic world the same action in the same state can land in different places, so $V$ and $Q$ are redefined as expectations, $Q(s, a) = \mathbb{E}\big[r(s, a) + \gamma \sum_{s'} P(s' \mid s, a) \max_{a'} Q(s', a')\big]$. The deterministic update now fails to converge, and you can hear why: it overwrites the entry with each new sample, so the estimate forever chases the latest lucky or unlucky transition instead of settling on the average. The repair is to blend rather than overwrite, with a learning rate that shrinks as a pair is revisited:

$$ \hat{Q}_n(s, a) \leftarrow (1 - \alpha_n)\,\hat{Q}_{n-1}(s, a) + \alpha_n\big[r + \gamma \max_{a'} \hat{Q}_{n-1}(s', a')\big], \qquad \alpha_n = \frac{1}{1 + \text{visits}_n(s, a)}. $$

Early visits move the estimate a lot, later visits barely nudge it, and the entry converges to the running average of its sampled targets, which is the expectation we redefined $Q$ to be. (First visit: $\alpha_1 = 1/2$. Fourth visit: $\alpha_4 = 1/5$. The pen slows as evidence accumulates, the same instinct as the bandit's sample average.) Flip the stochastic toggle in Fig 5.1 to feel the difference: values wobble, then settle. 

import numpy as np

def q_update(Q, s, a, r, s_next, gamma, alpha=None):
    target = r + gamma * np.max(Q[s_next])
    if alpha is None:
        Q[s, a] = target                                # deterministic world
    else:
        Q[s, a] = (1 - alpha) * Q[s, a] + alpha * target  # stochastic world
    return Q

# the worked example: r=0, gamma=0.9, next state's entries {63, 81, 100}
Q = np.zeros((10, 4)); Q[2] = [63, 81, 100, 0]
q_update(Q, s=1, a=0, r=0, s_next=2, gamma=0.9)[1, 0]   # -> 90.0

Right: $r + \gamma \max_{a'} \hat{Q}(s', a') = 2 + 45 = 47$, same arithmetic as the lecture's $0 + 0.9\max\{63, 81, 100\} = 90$. One entry overwritten, everything else untouched.

Check: why backward from the goal, and why does randomness demand a learning rate?

Two behaviours from Fig 5.1 to explain: values fill in goal-first, and the stochastic toggle needs $\alpha_n$.

Backward propagation. The update's only source of non-zero information is $r + \gamma \max_{a'} \hat{Q}(s', a')$. With rewards 0 away from the goal and a table initialized to 0, that expression is non-zero only where $r > 0$ (entering the goal) or where $s'$ already has a non-zero entry. Episode one can satisfy only the first condition, at the final step; each later episode satisfies the second one step further back. Information has no other channel: it must arrive via the next state's entries, so it crawls goal-outward, one transition per episode along the travelled path.

The learning rate. In a stochastic world the sampled target $r + \gamma \max_{a'} \hat{Q}(s', a')$ is a random variable: the same $(s, a)$ yields different targets on different visits because $s'$ varies. The deterministic rule assigns the newest sample as the whole truth, so the entry oscillates forever with the luck of the draw and never converges. Blending with $\alpha_n = 1/(1 + \text{visits}_n(s, a))$ makes the entry the average of all sampled targets (the same arithmetic as the bandit's incremental sample average), and averages converge to the expectation that stochastic $Q$ is defined to be.

Coding check: finish the update

A colleague writes the stochastic-world update as Q[s, a] = r + gamma * np.max(Q[s_next]) and cannot understand why the values keep oscillating during training. Fix the line and explain the two changes any correct fix must contain.

Answer. The line is the deterministic rule in a stochastic world. The fix is the blended update with a decaying learning rate:

alpha = 1 / (1 + visits[s, a])
Q[s, a] = (1 - alpha) * Q[s, a] + alpha * (r + gamma * np.max(Q[s_next]))

Change one: the new sample must be mixed into the old estimate, not replace it, so the entry tracks an average of targets rather than the latest draw. Change two: the mixing weight must shrink over visits (here $1/(1 + \text{visits})$), so early evidence moves the estimate freely and later noise cannot un-learn it. Keep visits incremented per $(s, a)$ pair, not globally, since each entry needs its own evidence count.

6. Summary and method card

Three settings, one thread. Bandits have no meaningful state: the challenge is that reward distributions are unknown, the tools are $\epsilon$-greedy and UCB, and what gets learned is the immediate action value $Q(a)$. Planning in MDPs has state and a fully known model: the challenge is uncertain and delayed consequences, and the tools are value iteration and policy iteration, both powered by Bellman's one-step recursion. Reinforcement learning proper has state and an unknown model: the challenge is learning a good policy from interaction alone, and the tool is Q-learning, the same Bellman recursion turned into an update rule driven by experience. Bandits learn $Q(a)$; MDPs need $Q(s, a)$ because actions affect future states; known models let us plan; unknown ones force us to learn.

Why is RL considered hard, harder than the supervised learning this course began with? Four structural reasons. Exploration versus exploitation: the agent chooses its own training data, and safe choices starve it of information. Delayed, sparse rewards: the credit-assignment problem of deciding which of sixty moves lost the game. Sample inefficiency: real interactions are expensive, and RL tends to need many. And stability and generalization: methods are sensitive to approximation error and distribution shift, since improving the policy changes the data the agent sees. Which points at the core difficulty, worth committing to memory: the agent must learn what to do while its own actions determine what it observes.

7. End-of-lesson quiz

Two quick checks, then four transfer questions that ask you to connect and decide, not recall. Attempt each before expanding the answer.

Quiz 1

A bandit algorithm learns $Q(a)$; Q-learning learns $Q(s, a)$. What exactly forces the extra argument?

The extra argument multiplies the table size by $|S|$; nobody pays that for convenience. It is forced by the structure of the problem.
Right. The bandit's reward depends only on $a_t$, so one value per action suffices. Once $(r_{t+1}, s_{t+1}) \sim p(\cdot, \cdot \mid s_t, a_t)$, the same action has different consequences in different states, and value must be indexed by both.
A bandit can have a thousand arms and an MDP two actions. The dimension count is not about how many actions exist but about what the reward and the future depend on.
Quiz 2

You are handed a complete, trusted MDP for a warehouse robot: exact $P$, exact $R$. Do you reach for Q-learning or value iteration, and why?

Right. Planning applies when the MDP is fully specified: sweep Bellman backups offline until convergence, extract the greedy policy, done. Q-learning would spend costly interaction rediscovering, sample by sample, what the model already states.
More general does not mean better here: generality is what you pay for when you lack a model. With $P$ and $R$ in hand, Q-learning's exploration and sample cost buy nothing that a few cheap offline sweeps do not already deliver, with guarantees.
Experience is the substitute for a model, not a prerequisite on top of one. A complete MDP already contains every fact experience could teach; value iteration just extracts the consequences.
Quiz 3 (transfer): the Markov property, from n-grams to MDPs

The n-gram lesson assumed the next word depends only on recent context; this lesson assumed the next state depends only on the current state and action. Make the parallel precise: what is the shared assumption, what does each model buy with it, and what is the shared failure mode?

Answer. Both are Markov assumptions: a bounded present, the last $n-1$ words or the current $(s_t, a_t)$, is treated as a sufficient statistic for the entire history when predicting what comes next. The n-gram buys tractable estimation: probabilities become countable tables over short contexts instead of over all possible documents. The MDP buys the Bellman recursion: because the future factors through the present state, value satisfies a one-step equation, $G_t = r_{t+1} + \gamma G_{t+1}$, and planning becomes local backups instead of trajectory enumeration. The shared failure mode is hidden history: when relevant information lives outside the summary (a long-range dependency in text; an unobserved variable like engine wear in the car), predictions are systematically wrong. And the shared repair is enriching the state, longer contexts for n-grams, more informative state variables for MDPs, trading table size for fidelity, the same trade both lessons keep making.

Quiz 4 (transfer): plan or learn? Two problems, two verdicts

Problem A: schedule elevator cars in a building whose arrival patterns you have modelled precisely from years of logs. Problem B: teach a robot hand to manipulate objects whose friction and weight vary unpredictably. For each, plan or learn, and what would change your answer?

Answer. A is planning territory: with a trusted $P$ and $R$, run value iteration (or policy iteration) offline and deploy the extracted policy; interaction adds cost and risk while teaching nothing the model does not already say. B is learning territory: friction and weight variation mean no reliable transition model exists, so the robot must estimate action values from its own experience, Q-learning style, balancing exploration against wear and breakage. What flips the verdicts is model quality. If the elevator model is stale (a new tenant changes traffic), the plan quietly degrades and learning from live data becomes attractive; if the robot's dynamics get captured in a good simulator, planning inside the simulator (or training there before transfer) recovers most of the model-based advantages. The decision rule from the lecture is the durable one: known $P$ and $R$, plan; unknown, learn; partially known, expect hybrids.

Quiz 5 (transfer): one softmax, three lessons

The exploration policy $P(a_i \mid s) = \exp(k\hat{Q}(s, a_i)) / \sum_j \exp(k\hat{Q}(s, a_j))$ looks exactly like formulas from logistic regression and soft K-means. What is the shared mechanism, and what does the constant $k$ correspond to in each setting?

Answer. The shared mechanism is the softmax: exponentiate a vector of scores, normalize to a probability distribution. It solves the same problem all three times, converting "how good is each option" numbers into calibrated probabilities that preserve ranking, stay positive, and sum to 1. In logistic regression the scores are class logits $w_c^\top x$ and the output is the probability of each label. In soft K-means the scores are negative scaled distances to centroids and the output is each point's cluster responsibilities, with the stiffness parameter sharpening or softening assignments. Here the scores are Q-values and the output is a stochastic policy. In every case $k$ (or its twin, the stiffness or inverse temperature) controls commitment: $k \to 0$ flattens toward uniform, ignore the scores entirely, and $k \to \infty$ collapses onto the argmax, trust them absolutely. RL adds one twist the other two lack: it varies $k$ over time, exploring while $\hat{Q}$ is unreliable and hardening as evidence accumulates. Soft K-means pulled the same annealing trick with its stiffness. Nothing in this course stays in its own chapter.

Quiz 6 (transfer): where the table breaks, and what deep RL does about it

Tabular Q-learning provably converges on the gridworlds of this lesson. Sketch why it collapses for chess or for a robot with camera input, and what structure the fix exploits.

Answer. Two collapses, one worse than the other. Storage: the table needs one entry per state-action pair, and chess has roughly $10^{43}$ board states while a modest camera image has more possible values than could ever be enumerated; no memory holds the table. Coverage is the deeper failure: tabular updates touch only entries the agent has visited, and in a space that vast the agent will essentially never see the same state twice, so almost every lookup at decision time hits an untouched zero. The table has no mechanism to say "this position resembles one I know"; every state is a stranger. The fix replaces the table with a function approximator, $Q(s, a; \theta)$ as a neural network, so that similar states map to similar values and experience in one state informs millions of unvisited neighbours. That is deep reinforcement learning, the marriage of this lesson's decision framework with the representation learning of the neural-network lectures, and it is what carried these ideas from 3×3 grids to Atari and AlphaGo. The cost, as the lecture warned: approximation surrenders the clean tabular convergence guarantees, which is where the stability challenges of modern RL begin.

And that is the course. Twenty-one lectures ago, the first algorithm we ever built answered questions by trusting labelled neighbours; it needed someone to have written down every answer in advance. Since then the supervision kept thinning: regression fit curves to targets, classifiers drew boundaries between given classes, unsupervised methods found clusters and components with no labels at all. This final lesson took the last step: no labels, no targets, just a number that arrives after you act, and from that alone an agent taught itself the way home, watching value radiate backward from the goal, one Bellman backup at a time. From matching answers, to finding structure, to learning behaviour. The tables will not scale, so these ideas now ride on the neural networks from the middle of the course, and that combination, decisions plus deep function approximation, is where this field is still being written. Go build something that learns.
