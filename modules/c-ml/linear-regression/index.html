Linear Regression

The first parametric model of the course, and the template for every model that follows. We pick a family of functions, we measure how wrong each one is, and we search for the least wrong one. That three-step recipe, model, loss, optimization, is the whole of modern machine learning in miniature. This lesson builds it from scratch: every concept gets an animation, an interactive figure, or a piece of code you can step through line by line.

0. Four prediction problems

Before any math, four questions you have probably asked this week:

🎬
What should I watch tonight?
Netflix predicts a match score for you: 91%
⭐
How good is this movie?
A rating on a continuous scale: 7.8 / 10
📈
How many followers will I have next month?
A count that grows over time: 12,400
🏠
What is this house worth?
A price in dollars: $842,000

Look at the answers, not the questions. A match percentage, a rating, a follower count, a price. Every one of them is a continuous number. Not a category, not a yes or no, a number that can land anywhere on a scale. Predicting a continuous number from data is called regression, and it is one of the two great problem types in supervised learning. The other, predicting a discrete category, is classification. You have already met classifiers in this course: kNN votes on a label, a decision tree routes you to a leaf with a class in it. Today the output is a number.

1. Regression vs classification

The split is about the target $t$, the thing you want to predict. If $t$ is a real number (a movie rating in $[0, 10]$, a follower count, a house price), the problem is regression. If $t$ is a label from a finite set (spam or not, cat or dog or bird), the problem is classification. Same inputs, same data-collection story, different output type, and, as you will see over the next few lectures, different losses and different models.

The figure below makes the split physical. The same cloud of points can be read both ways. In regression mode, the vertical axis is the target, and the model is a line chasing the trend. Flip the switch and the vertical axis becomes just another input feature, the targets collapse into two colours, and the model becomes a boundary separating them. Watch the morph.

Fig 1.1, one dataset, two readings. Toggle between regression (fit a line to continuous targets) and classification (separate two classes with a boundary).

2. The modular view of ML

Here is the scaffold this whole lesson hangs on, and honestly, the scaffold the whole course hangs on. Every supervised learning method you will ever meet decomposes into the same five modules:

Fig 2.1, the five modules. Pick a model class, score candidates with an objective, optimize to find the best one, check it generalizes, and regularize when it does not.

Model
A function that represents the relationship between an input $x$ and a target $t$. The model class is the family the function is chosen from: kNN, decision trees, linear regression, neural networks. Each family comes with parameters and a learning algorithm.
Objective function
Also called the loss, cost, error, or (flipped in sign) utility function. It measures how well a particular candidate model fits the training examples: the pairs $(x^{(i)}, t^{(i)})$ for which we already know the answer.
Optimization
The search for the parameters that minimize the loss, possibly with a regularizer added. This is where the "learning" in machine learning actually happens.
Generalization
How well the trained model predicts held-out data, validation or test, that it never saw during training. Fitting the training set is easy. Generalizing is the whole game.
Regularization
Restricting the model's capacity, for example by keeping weights small, so that it generalizes better. You trade a bit of training fit for a lot of test performance.

Keep this picture in your head. kNN and decision trees blurred these modules together. Linear regression is the first model where each module is a separate, visible, swappable part. When we get to neural networks, nothing in this picture changes except the model class.

3. Linear regression, the high-level pitch

What it is: a model that predicts a continuous target as a weighted sum of the input features, plus a constant. What it does: draws the straight line (or plane, or hyperplane) through your data that best matches the trend. Why it is useful: it is simple, it is interpretable, every weight tells you how much one feature moves the prediction, and it is a strong baseline that more complicated models must beat to justify their complexity.

The classic use case. A realtor prices houses. Each sale she has seen is a data point: size in square feet in, sale price out. Over years she internalizes the trend, and when a new listing comes along she can price it without a spreadsheet. Linear regression is that intuition made explicit: it looks at the same scatter of past sales and settles on the trend line, and then a new house's price is just the height of the line at that house's size. Watch her learn:

Fig 3.1, the realtor's intuition. Past sales appear one by one, the asking line settles toward the trend, and a new listing gets priced by reading the line.

One honest caveat before the math. The data never sits exactly on a line. We assume each observed target was generated by some unknown true function $f$ plus noise: $t = f(x) + \epsilon$. The line is our stand-in for $f$, and the noise $\epsilon$ is everything the line cannot explain: measurement error, missing information, plain randomness. We will return to noise in section 10, because it is the reason overfitting exists.

4. Back to high-school math

You already know this model. In high school it was

$$ y = mx + b $$

a slope $m$ and an intercept $b$. Machine learning keeps the exact same object and renames the parts, because we are about to need many more of them than two:

$$ y(x) = w_0 + w_1 x \;\approx\; t = f(x) + \epsilon $$

$w_0$ is the intercept (the old $b$), $w_1$ is the slope (the old $m$), and together they are the weights or parameters of the model, the numbers the machine will learn from data. The assumption baked into this model class is mild but real: changes in $x$ are associated with roughly linear changes in $t$. Double the size, roughly double the price bump. When that assumption is badly wrong, the model is badly wrong, and no amount of clever optimization fixes it.

Get a feel for the two weights before we let the machine touch them. In the playground below, you are the optimizer. Drag the sliders and watch the line, the equation, and the fit change together.

Fig 4.1, the $y = w_0 + w_1 x$ playground. Slide the intercept and slope, watch the equation and the fit respond live. Try to make the line hug the points.

Two things you probably noticed. First, $w_0$ lifts the whole line up and down while $w_1$ pivots it, the two weights do different jobs. Second, you can eyeball a decent fit but you cannot be sure it is the best fit. "Best" needs a definition. That definition is the loss function, and it arrives in section 6. First, let us make the model handle more than one input.

5. Simple vs multiple regression

A house is not just its size. It has a number of bedrooms, an age, a distance to downtown. With $D$ features, $x \in \mathbb{R}^D$, the model grows one weight per feature:

$$ y(x) = w_0 + w_1 x_1 + w_2 x_2 + \cdots + w_D x_D = w_0 + \sum_{j=1}^{D} w_j x_j $$

Each weight $w_j$ answers a plain question: holding everything else fixed, how much does the prediction move when feature $j$ increases by one unit? That per-feature readability is why linear regression survives in economics, medicine, and every field that has to explain itself.

The intercept $w_0$ is the awkward one in that sum, it has no feature attached. The standard trick: give it one. Prepend a constant feature $x_0 = 1$ to every example. Then

$$ x = (1, x_1, \dots, x_D)^\top, \quad w = (w_0, w_1, \dots, w_D)^\top, \quad y(x) = w^\top x $$

The whole model collapses into a single dot product. Check the dimensions: $x \in \mathbb{R}^{D+1}$, $w \in \mathbb{R}^{D+1}$, and their dot product $y \in \mathbb{R}$ is one number, the prediction.

Loops vs vectorized code

Here is the dot product as a Python beginner would write it, and as a practitioner would write it:

Naive loop
y = w[0]
for j in range(1, D + 1):
    y += w[j] * x[j]
Vectorized
y = np.dot(w, x)

Same math, wildly different execution. The loop crawls through Python's interpreter one element at a time and assumes sequential processing. The vectorized call hands the whole computation to an optimized linear algebra library in one step. Vectorizing your code matters for four reasons: it is simpler and more readable, it cuts interpreter overhead, it uses linear algebra routines tuned over decades, and it exploits parallel hardware, GPUs above all. The slide's framing is worth repeating: vectorization is one of the reasons AI became scalable at all. Race them yourself:

Fig 5.1, the race. Both sides compute the same dot product $y = w^\top x$. The loop processes one component per tick; the vectorized path resolves in a single fused step. Crank $D$ and watch the gap explode.

The design matrix

One more packaging step and we are done with notation for the whole lesson. To predict for all $N$ training examples at once, stack them as rows of a matrix $X$, the design matrix, with the column of 1s built in. One matrix multiply computes every prediction simultaneously:

Fig 5.2, the design matrix. Rows are examples, columns are features, the first column is all 1s so the intercept rides along in $w$. One multiply, $N$ predictions.

A concrete shapes check, because shapes are where every implementation bug lives. Say $N = 100$ houses and $D = 3$ features. Then $X$ is $100 \times 4$ (the extra column is the 1s), $w$ is $4 \times 1$, and $Xw$ is $100 \times 1$: one prediction per house. Two more shapes we will need in section 9: $X^\top t$ is $(4 \times 100)(100 \times 1) = 4 \times 1$, and $X^\top X$ is $(4 \times 100)(100 \times 4) = 4 \times 4$.

Check your understanding

With $X \in \mathbb{R}^{N \times (D+1)}$ and $w \in \mathbb{R}^{(D+1) \times 1}$, what is the shape of the scalar-or-not quantity $w^\top X^\top X w$?

That is the shape of the middle piece $X^\top X$ alone. Keep multiplying: the outer $w^\top (\cdot) w$ squeezes it down.
Right. Chain the shapes: $(1 \times (D{+}1)) \cdot ((D{+}1) \times N) \cdot (N \times (D{+}1)) \cdot ((D{+}1) \times 1) = 1 \times 1$. In fact $w^\top X^\top X w = \lVert Xw \rVert^2$, the squared length of the prediction vector.
That is the shape of $Xw$, the vector of predictions. Here it gets hit with $X^\top$ and then $w^\top$ from the left.
Inner dimensions would not even match up to produce that here. Write each factor's shape and cancel neighbours.
Coding check: multiply two matrices with no built-ins. What does it cost?

Write matrix multiplication for $A \in \mathbb{R}^{n \times m}$ and $B \in \mathbb{R}^{m \times p}$ using only loops, then state its time complexity.

def matmul(A, B):
    n, m, p = len(A), len(B), len(B[0])
    C = [[0.0] * p for _ in range(n)]
    for i in range(n):          # each output row
        for j in range(p):      # each output column
            for k in range(m):  # the dot product
                C[i][j] += A[i][k] * B[k][j]
    return C

Three nested loops over $n$, $p$, $m$, so the cost is $O(nmp)$, cubic $O(n^3)$ for square matrices. np.dot computes exactly this, but in compiled, cache-aware, parallel code, which is why it wins the race in Fig 5.1 by orders of magnitude. The complexity class is the same, the constant factor is not even close.

6. The loss function

Show a fresh, untrained model a scatter plot and it has no intuition at all. It cannot squint at the trend the way you did in Fig 4.1. From the model's point of view, every candidate line, the good, the bad, and the upside-down, is just a different setting of $(w_0, w_1)$, and nothing so far tells it which setting to prefer. We owe the machine a definition of good. That definition is the loss function.

Build it in three moves, and watch each move land in the figure below.

Move 1: the residual. For one training example, the model predicts $y$ and the truth is $t$. The gap $y - t$ is the residual, the vertical distance from point to line. Small residuals mean the line passes close to the point.

Move 2: square it. Residuals come in both signs, and we do not want an error of $+3$ cancelling an error of $-3$. Squaring kills the sign and, as a bonus, punishes big misses more than small ones. The squared error for one example, with a factor of one half whose job is purely to make later derivatives clean:

$$ L(y, t) = \tfrac{1}{2}\,(y - t)^2 $$

Move 3: average over the training set. A line is good if it is close to all the points, so we average the squared errors over all $N$ examples. This is the empirical loss, and it is the single number we will ask optimization to drive down:

$$ J(w) = \frac{1}{2N} \sum_{i=1}^{N} \big( y^{(i)} - t^{(i)} \big)^2 = \frac{1}{2N} \sum_{i=1}^{N} \big( w^\top x^{(i)} - t^{(i)} \big)^2 $$

The ideal weight vector is the one that minimizes it: $w^\star = \arg\min_w J(w)$. Now derive the loss on screen instead of on faith. Drag the line, switch on the residuals, square them, and watch $J(w)$ respond:

Fig 6.1, deriving the loss. Drag the line, then toggle residuals (vertical gaps) and squares (each square's area is one squared error). $J(w)$ is their average, updating live. Minimize it by hand if you can.

Try to beat the Best fit button. You will get close, humans are good at this in 2D, but you will almost never tie it, and in 10 dimensions you would not stand a chance. That is precisely the gap optimization exists to close.

7. Data space vs weight space

This is the most important mental picture in the lesson. Everything we have drawn so far lives in data space: axes are $x$ and $t$, points are training examples, and a candidate model is a line. Now build a second picture. Let the axes be $w_0$ and $w_1$. In this weight space, an entire candidate line collapses to a single point: the pair $(w_0, w_1)$ that defines it. And every point in weight space carries a number, its loss $J(w)$.

So the loss is a landscape over weight space. For squared error that landscape is a smooth bowl, and its contour lines are ellipses. Learning has a geometric meaning now: find the lowest point of the bowl. The two panels below are two views of one reality. Drag the line on the left and you drag a point across the loss landscape on the right. The three preset candidates, red, green, and yellow, are the lecture's three lines: jump between them, see which sits deepest in the bowl, then press Solve to snap to the exact bottom.

Fig 7.1, the signature picture. Left: data space, where a model is a line. Right: weight space, where the same model is a point on the loss contours. One drag moves both. Solve snaps to the normal-equation optimum at the centre of the ellipses.

Hold on to this duality. Every optimizer in this course, from the normal equation to stochastic gradient descent on a billion-parameter network, is a strategy for moving a point through weight space toward low loss. The only things that change later are the dimension of the space and the shape of the landscape.

8. Optimization from first principles

How do you find the bottom of a smooth valley without seeing the whole landscape? Calculus gives the classical answer: at a minimum of a smooth function, the ground is flat. The derivative is zero. Points where the derivative vanishes are called critical points, and for a function shaped like a single valley, the critical point is the minimum.

A fully worked one-variable example, the one from the lecture:

$$ f(x) = \frac{x^4}{4} - x, \qquad \frac{df}{dx} = x^3 - 1 \stackrel{!}{=} 0 \;\Rightarrow\; x_{\min} = 1, \qquad f(1) = \tfrac14 - 1 = -\tfrac34 $$

Set the derivative to zero, solve, done. (Careful arithmetic matters: $f(1)$ is $-0.75$, not $0.75$.) Feel the idea rather than memorizing it, drag the point along the curve and watch the tangent line tilt, flatten, and tilt back:

Fig 8.1, critical points. Drag the point along $f(x) = x^4/4 - x$. The tangent's slope is the derivative; it hits exactly zero at $x = 1$, the bottom of the valley.

Warm-up before the main event

Find the minimum of $f(x) = x^2 - 4x + 4$.

Check by differentiating: $f'(x) = 2x - 4$, which is not zero at $x = 0$.
Correct. $f'(x) = 2x - 4 = 0$ gives $x = 2$, and $f(2) = 4 - 8 + 4 = 0$. You can also spot that $f(x) = (x-2)^2$, a shifted parabola touching zero.
Right location, wrong value: plug $x = 2$ back in. $4 - 8 + 4 = 0$.
The $x^2$ term dominates for large $|x|$ in both directions, so the parabola opens upward and must bottom out.

More than one variable: the gradient

Our loss $J(w_0, w_1)$ has two knobs, so "derivative" becomes one partial derivative per knob, stacked into a vector called the gradient:

$$ \nabla_w J = \frac{\partial J}{\partial w} = \left( \frac{\partial J}{\partial w_0}, \dots, \frac{\partial J}{\partial w_D} \right)^{\!\top} \in \mathbb{R}^{(D+1) \times 1} $$

The gradient points in the direction of steepest increase, and its negation points steepest downhill. "Derivative equals zero" becomes "gradient equals the zero vector". The lecture's worked two-parameter example:

$$ \min_{w_0, w_1} \; J(w_0, w_1) = (w_0 - 1)^2 + (w_1 - 2)^2, \qquad \nabla_w J = \begin{pmatrix} 2(w_0 - 1) \\ 2(w_1 - 2) \end{pmatrix} \stackrel{!}{=} \begin{pmatrix} 0 \\ 0 \end{pmatrix} \;\Rightarrow\; w^\star = \begin{pmatrix} 1 \\ 2 \end{pmatrix} $$

Same recipe as 1D: set every slope to zero simultaneously, solve. Watch the gradient arrow shrink to nothing as you approach the optimum:

Fig 8.2, the 2D version. Drag the probe over the contours of $(w_0-1)^2 + (w_1-2)^2$. The arrow is the negative gradient, always pointing downhill, vanishing at $w^\star = (1, 2)$.

Two ways to optimize

Everything downstream of "set the gradient to zero" splits into two roads:

  1. Analytical. Set $\nabla_w J = 0$ and solve for $w$ in closed form, with algebra, once.
  2. Iterative. Start somewhere, repeatedly nudge $w$ to reduce $J$, stop when it flattens out.

Linear regression is special: it is one of the few models where the analytical road exists. Most of modern ML, neural networks included, has no closed form and lives entirely on the iterative road. We will walk both, analytical first.

The analytical solution in 1D

For the simple model $y = w_0 + w_1 x$, setting both partial derivatives of $J$ to zero and solving the two resulting equations gives closed-form answers. With $\bar{x}$ and $\bar{t}$ denoting the means of the inputs and targets:

$$ w_1^\star = \frac{\sum_i (x^{(i)} - \bar{x})(t^{(i)} - \bar{t})} {\sum_i (x^{(i)} - \bar{x})^2}, \qquad w_0^\star = \bar{t} - w_1^\star \bar{x} $$

Read them as sentences. The slope is how much $x$ and $t$ vary together, divided by how much $x$ varies alone. The intercept then shifts the line so it passes through the centre of mass $(\bar{x}, \bar{t})$ of the data.

Worked by hand: three points, full arithmetic

Data: $(1, 2),\; (2, 3),\; (3, 5)$.

Means. $\bar{x} = \frac{1+2+3}{3} = 2$, $\;\bar{t} = \frac{2+3+5}{3} = \frac{10}{3} \approx 3.333$.

Slope numerator (co-variation):

$$ (1-2)(2 - \tfrac{10}{3}) + (2-2)(3 - \tfrac{10}{3}) + (3-2)(5 - \tfrac{10}{3}) = (-1)(-\tfrac43) + 0 + (1)(\tfrac53) = \tfrac43 + \tfrac53 = 3 $$

Slope denominator (spread of $x$):

$$ (1-2)^2 + (2-2)^2 + (3-2)^2 = 1 + 0 + 1 = 2 $$

Weights. $w_1^\star = \frac{3}{2} = 1.5$, and $w_0^\star = \frac{10}{3} - 1.5 \times 2 = \frac{10}{3} - 3 = \frac{1}{3} \approx 0.333$.

Sanity check. The fitted line $y = \frac13 + \frac32 x$ predicts $1.833,\; 3.333,\; 4.833$ for the three inputs, residuals $-0.167,\; +0.333,\; -0.167$. They do not cancel to zero by luck: least squares always makes residuals sum to zero when an intercept is present. The loss is $J = \frac{1}{2 \cdot 3}(0.0278 + 0.1111 + 0.0278) \approx 0.0278$, and no other line does better.

The analytical solution in general: the normal equation

With the design matrix in hand, the same derivation runs in any dimension. Write the loss in matrix form, take the gradient, set it to zero:

$$ J(w) = \tfrac{1}{2} \lVert Xw - t \rVert_2^2, \qquad \nabla_w J = X^\top X w - X^\top t \stackrel{!}{=} 0 \;\Rightarrow\; w^\star = (X^\top X)^{-1} X^\top t $$

That is the normal equation, the entire training procedure in one line of algebra. (The gradient identity is Eq. 84 of the Matrix Cookbook; deriving it yourself is homework, and the shapes check below is the guard rail for that derivation.) In code, prefer solve to an explicit inverse, it is faster and numerically safer: 

w = np.linalg.solve(X.T @ X, X.T @ t)   # never np.linalg.inv(X.T @ X) @ X.T @ t

Dimensions check with our running shapes, $N = 100$, $D = 3$: $X^\top X$ is $4 \times 4$, $X^\top t$ is $4 \times 1$, so we solve a $4 \times 4$ linear system for the $4 \times 1$ weight vector. The training set size $N$ has vanished from the system's size, it only shaped the ingredients.

So why does the rest of ML not just use this? Two problems:

  • Few models are so lucky. The closed form exists because linear regression's loss is a perfect quadratic bowl. Change the model even slightly (logistic regression, any neural network) and no closed form exists at all.
  • It scales badly in $D$. Solving the system costs $O(D^3)$, and $X^\top X$ may not even be invertible. With $D$ in the millions, as in modern models, $D^3$ is fantasy.

Which brings us to the road everything else in ML travels.

9. Gradient descent

The iterative idea fits in one sentence: stand somewhere on the loss landscape, feel which way is downhill, take a small step that way, repeat. "Feel which way is downhill" is exactly what the gradient gives us, it points uphill, so we step against it. Initialize $w$ somewhere (zeros work here), then loop:

$$ w_j \leftarrow w_j - \alpha \frac{\partial J}{\partial w_j} \qquad \text{or, all coordinates at once,} \qquad w \leftarrow w - \alpha \frac{\partial J}{\partial w} $$

The scalar $\alpha > 0$ is the learning rate, the step size, and it is a hyperparameter: you choose it, the model does not learn it. Larger $\alpha$ moves faster; typical values are small, like $0.01$ or $0.0001$. (One bookkeeping note: if you minimize the total loss instead of the average, every gradient is $N$ times bigger, so use a correspondingly smaller $\alpha' = \alpha / N$. Same algorithm, rescaled step.)

Why does stepping against the gradient work? See it cleanly in 1D, where the gradient is just a slope. If $\nabla J > 0$, the ground rises to the right, so go left: decreasing $w$ decreases $J$. If $\nabla J < 0$, the ground falls to the right, so go right. In both cases, the sign of the gradient points the way downhill, and the update rule obeys it automatically because of the minus sign.

For linear regression specifically, the gradient of $J$ works out to an average of residual-weighted inputs, giving the specialized update:

$$ w \leftarrow w - \frac{\alpha}{N} \sum_{i=1}^{N} \big( w^\top x^{(i)} - t^{(i)} \big)\, x^{(i)} $$

Read it as a story: each training example pushes on the weights with a force proportional to how wrong the model is on it (the residual), in the direction of its own features. Points the model overshoots push one way, points it undershoots push the other, and the line settles where the pushes balance.

Worked by hand: one gradient-descent step, real numbers

Two points, $(1, 2)$ and $(2, 3)$. Start at $w = (w_0, w_1) = (0, 0)$ with $\alpha = 0.5$. With augmented inputs $x^{(1)} = (1, 1)$, $x^{(2)} = (1, 2)$:

Predict. Both predictions are $0$, so the residuals are $y - t = -2$ and $-3$.

Gradient. $\frac{\partial J}{\partial w_0} = \frac{1}{2}\big[(-2)(1) + (-3)(1)\big] = -2.5$, $\;\frac{\partial J}{\partial w_1} = \frac{1}{2}\big[(-2)(1) + (-3)(2)\big] = -4$.

Step. $w_0 \leftarrow 0 - 0.5 \times (-2.5) = 1.25$, $\;w_1 \leftarrow 0 - 0.5 \times (-4) = 2$.

Did it help? The loss drops from $J = \frac{1}{4}(4 + 9) = 3.25$ to $\frac{1}{4}(1.5625 + 5.0625) \approx 1.66$, roughly halved in one step. The negative gradient said "raise the intercept, raise the slope", the model was undershooting everything, and it was right.

The loss bowl in 3D

Since our loss has two weights, the landscape $J(w_0, w_1)$ is a surface over the plane, and for squared error it is a bowl: a paraboloid with a single bottom. Gradient descent is a ball rolling down it in discrete steps. The figure below is the real loss surface for the dataset shown, not a stock image. Rotate it, drop the ball where you like, and pay attention to what the learning rate does:

Fig 9.2, the loss bowl. Drag to rotate. Choose $\alpha$, step or play, and toggle batch vs stochastic. Small $\alpha$ crawls, large $\alpha$ overshoots and diverges, stochastic steps are cheap but noisy. The inset shows the 1D sign-of-the-gradient rule driving every step.

Three behaviours worth burning into memory, all reproducible in the figure:

  • Crawling. $\alpha$ too small: every step is safe and microscopic. You will converge sometime next semester.
  • Diverging. $\alpha$ too large: each step overshoots the valley and lands higher than it started. The loss explodes. This is the single most common training bug in practice.
  • Noisy but cheap. Stochastic mode estimates the gradient from one random example instead of all $N$. Each step costs $1/N$ as much, and the path jitters yet still finds the valley. Full-batch uses all examples per step; mini-batches sit in between.

Why gradient descent wins anyway

It seems absurd to trade a one-line exact formula for a loop of guesses. The trade is the best deal in machine learning:

  • It is easier to implement than direct solutions, five lines beat a linear-system solver.
  • It works when no closed form exists, which is nearly always. This is the only reason deep learning is trainable at all.
  • It is cheaper in high dimensions. The normal equation pays $O(D^3)$ for the solve. One gradient-descent step costs $O(ND)$, so $t$ steps cost $O(tND)$, and stochastic steps cost even less. When $D$ is huge, iteration wins by an enormous margin.

And the honest caveats, each of which becomes a lecture later in the course:

  • It needs $J$ to be differentiable, no gradients, no descent.
  • It is sensitive to the initialization and to the choice of $\alpha$.
  • It carries no guarantee of finding the global minimum in general. It follows the local slope, so it can settle into a local dip. The rescue here: a function is convex if it curves upward everywhere, a bowl with no side pockets, and for convex losses every local minimum is global. Our squared loss is convex, it is a sum of convex functions, so gradient descent with a sane $\alpha$ is safe for linear regression. Deep networks get no such promise.
Check your understanding

Gradient descent converged on some loss function. Under which condition are you guaranteed it found a global minimum?

A small $\alpha$ prevents overshooting but does nothing about the landscape's shape. On a two-valley loss, a careful walker still ends up in whichever valley it started above.
Right. Convexity means the landscape has one basin, so the local dip you settle into must be the global one. Squared-error linear regression is convex; neural network losses are not, which is why initialization folklore exists.
Counterexample: $f(w) = w^4 - 2w^2$ has two minima, and gradient descent finds whichever is downhill of its start.
Too pessimistic. Structure of the loss buys guarantees, and convexity is the classic structure that does.
Check: closed form vs gradient descent, when do you pick which?

List the trade-offs between solving the normal equation and running gradient descent for linear regression. Then decide: $D = 10$ features and $N = 10{,}000$ examples, which do you use? What about $D = 10^6$?

Answer. The normal equation is exact, has no hyperparameters, and needs no iteration babysitting, but it costs $O(D^3)$ to solve, requires $X^\top X$ to be invertible, and only exists for special models. Gradient descent is approximate and needs $\alpha$ chosen well, but each step is $O(ND)$ or less, it never forms a $D \times D$ system, and it generalizes to any differentiable model. At $D = 10$, a $11 \times 11$ solve is instant: use the normal equation. At $D = 10^6$, a $10^6 \times 10^6$ matrix does not even fit in memory: gradient descent, almost certainly stochastic, is the only option.

10. Noise, generalization, regularization

Time to cash the cheque from section 3: data is $t = f(x) + \epsilon$, truth plus noise. Where does $\epsilon$ come from? Four places, and every real dataset has all four:

  • Input noise: the features are measured imprecisely. The listed square footage is off by a hundred.
  • Label noise: the targets are wrong or inconsistent. The sale price was typed with a missing zero.
  • Missing or latent variables: factors that matter, renovation quality, the neighbour's dog, are simply not in the data.
  • Model mismatch: the model class is too simple for the true pattern. No line fits a curve.

That last item tempts us toward more powerful models. Here is the elegant way to get power without abandoning linear regression: basis functions. Feed the model transformed copies of the input. With powers of $x$ as the new features, an $M$-th order polynomial:

$$ y(x, w) = w_0 + w_1 x + w_2 x^2 + \cdots + w_M x^M = \sum_{j=0}^{M} w_j x^j $$

Read the indices carefully: here $x^j$ is the $j$-th power of $x$, not the $j$-th data point. The crucial observation: this is still linear regression. The model is linear in the weights $w$, which is all the normal equation and gradient descent ever cared about. Same loss, same optimizers, the design matrix just has columns $1, x, x^2, \dots, x^M$. The curve through data space bends, the machinery does not. (The figure lineage here is Bishop's PRML, the most famous overfitting plot in the field.)

So crank $M$ up and fit anything? Try it. The figure below fits a polynomial to noisy samples from a true curve, and splits off held-out test points the model never trains on:

Fig 10.1, overfitting, live. Left: the data, the true curve (dashed), and the degree-$M$ fit. Right: train and test loss vs $M$. Push $M$ to 9 and watch the wiggle; add data with the $N$ control and watch the wiggle die; open the weights table and watch the coefficients explode.

What you just saw, named:

  • At $M = 9$ with few points, the curve threads every training dot, including the noise. That is overfitting: the model memorized $\epsilon$.
  • Train loss falls monotonically as $M$ grows, it must, more capacity can only fit training data better. But test loss falls, bottoms out, and turns back up: the classic U-shaped generalization curve. The gap between the two curves is the price of memorizing noise.
  • More data helps. At $M = 9$ with $N = 100$ points, the same capacity has too many witnesses to lie to, and the fit calms down. But you cannot always get more data.
  • The weights table shows the mechanism: to chase noise, the fitted weights balloon to absurd magnitudes that nearly cancel. Huge weights mean a few input directions dominate the prediction, which is fragile far beyond this plot.

L2 regularization, ridge regression

That last bullet is the lever. Overfit models have huge weights, so punish huge weights. Add to the loss a penalty on the squared length of $w$:

$$ \tilde{J}(w) = J(w) + \lambda R(w) = \sum_{i=1}^{N} \big( w^\top x^{(i)} - t^{(i)} \big)^2 + \lambda\, w^\top w $$

The hyperparameter $\lambda \ge 0$ sets the exchange rate in a genuinely multi-objective trade: fit the data, but keep the weights small, and $\lambda$ decides how much fit one unit of weight-size is worth. Statisticians call the squared-weight penalty ridge regression; the deep learning community calls it weight decay. Same object, two fields, one idea.

Both training roads absorb the penalty with one-line changes. Gradient descent:

$$ w \leftarrow w - \alpha \left( \frac{\partial J}{\partial w} + \lambda w \right) = (1 - \alpha \lambda)\, w - \alpha \frac{\partial J}{\partial w} $$

The rewritten form explains the "decay" name: every step first shrinks the weights by the factor $(1 - \alpha\lambda)$, then applies the usual gradient push. The weights literally decay unless the data argues to keep them. And the closed form just grows a $\lambda$ on its diagonal:

$$ w = (X^\top X + \lambda I)^{-1} X^\top t $$ 
w = np.linalg.solve(X.T @ X + lam * np.eye(d), X.T @ t)   # ridge, one changed line

As a bonus, the $+\lambda I$ makes the matrix invertible even when $X^\top X$ alone is not, healing the other failure mode of the normal equation. Now take the disaster from Fig 10.1, keep $M = 9$, and dial in the cure:

Fig 10.2, ridge regression. Slide $\lambda$: the degree-9 fit relaxes toward smoothness, the weight bars shrink, and test loss falls, bottoms out, then rises again when $\lambda$ is so big the model underfits. The sweet spot is startlingly small.

Notice how tiny the good $\lambda$ is, the lecture's example uses $\lambda = e^{-18}$, and even that is enough to tame the degree-9 monster. How do you choose $\lambda$ in practice? Not by looking at the test set, that is cheating you can only do once. You hold out a validation split and pick the $\lambda$ that generalizes best to it: cross-validation, coming in its own right later in the course.

11. Miscellany: why squared error?

Of all the ways to punish a residual $r = y - t$, why square it? Run the alternatives through their failure modes, and watch each one fail in the figure:

  • $L = y - t$: signed errors cancel. A model that misses by $+5$ and $-5$ scores a perfect zero. Useless.
  • $L = |y - t|$: fixes the sign, but has a kink at zero where the derivative does not exist, which complicates gradient-based optimization. (It is used in practice, as robust "L1 loss", but it costs you the clean calculus.)
  • $L = (y - t)^3$: odd power, so it is signed like the raw residual and cancels the same way. Worse, it rewards errors of one sign.
  • $L = (y - t)^{2n}$ for large $n$: even and smooth, but it distorts the fit. Residuals smaller than 1 get crushed toward zero and effectively ignored, while the single largest residual dominates everything, so the fit chases outliers.

Fig 11.1, loss shapes. The candidates as functions of the residual. Toggle each curve: see the sign problem of the odd powers, the kink in $|r|$ at zero, and how $r^{2n}$ flattens tiny residuals into invisibility while exploding on big ones.

Squared error is the sweet spot: always non-negative, smooth everywhere, convex, admits a closed form, and, when you get to probabilistic ML, it is exactly the loss that maximum likelihood hands you under Gaussian noise. Every box ticked.

One pointer before we close, flagged in lecture but not derived: gradient descent uses only the first derivative. You can go further and use the second derivative, the curvature, to take smarter steps. That is Newton's method, and it will come back when we discuss optimization more deeply.

12. Summary and method card

Three steps to a prediction. Choose a model class. Define a loss. Optimize the parameters, analytically when the model is kind enough to allow it, iteratively otherwise. Assess the result by its generalization to held-out data, improve generalization with regularization, and choose the regularization strength by cross-validation. That recipe is not the linear regression recipe. It is the machine learning recipe, and it reappears intact in classification, neural networks, and deep learning.

Method card · Linear regression
Model$y = w^\top x$, with $x_0 = 1$ absorbing the intercept. Linear in $w$, features may be basis-expanded (polynomials).
LossMean squared error $J(w) = \frac{1}{2N}\sum_i (w^\top x^{(i)} - t^{(i)})^2$. Convex.
Optimizer, exactNormal equation $w^\star = (X^\top X)^{-1} X^\top t$. Cost $O(D^3)$. Use np.linalg.solve.
Optimizer, iterativeGradient descent $w \leftarrow w - \frac{\alpha}{N}\sum_i (w^\top x^{(i)} - t^{(i)}) x^{(i)}$. Cost $O(ND)$ per step, stochastic variant cheaper.
Key hyperparametersLearning rate $\alpha$, polynomial degree $M$, ridge strength $\lambda$.
Failure modesNonlinear truth (model mismatch), overfitting at high $M$ or low $N$, divergence when $\alpha$ too big.
RegularizerRidge $+\lambda w^\top w$: closed form $(X^\top X + \lambda I)^{-1} X^\top t$, update $(1-\alpha\lambda)w - \alpha \nabla J$. Pick $\lambda$ by cross-validation.

Where this sits in the course story: similarity (kNN), then rules (decision trees), and now parametric functions, model families, losses, optimization, regularization. The recipe you learned today never changes again. Only the model class does.

13. End-of-lesson quiz

Four quick checks, then four transfer questions that ask you to use the ideas, not recite them. Attempt each before expanding the answer.

Quiz 1

Fitting a degree-4 polynomial to exactly 5 data points. What happens to train and test error?

A degree-4 polynomial has 5 free coefficients, plenty for 5 points, so it will not underfit the training set.
The first half is right for training data only. The interpolating curve swings wildly between the points, and test data lives between the points.
Exactly. Five coefficients against five points means perfect interpolation, noise and all. This is the M = 9 disaster of Fig 10.1 in miniature: memorization, not learning.
Quiz 2

Your gradient-descent loss goes 10, 45, 380, 6200, ... What is the diagnosis and the fix?

Right. Exploding loss is the signature of divergence: each step lands on the far wall of the bowl, higher than it started. You saw it live in Fig 9.2.
Too-small $\alpha$ produces the opposite signature: the loss creeps down painfully slowly, it does not explode.
Non-convexity risks bad valleys, not explosions, and our squared loss is convex anyway.
Dataset size does not cause divergence. The step size does.
Quiz 3 (transfer): design a loss that is robust to outliers

Squared error chases outliers because the penalty grows quadratically. Propose a loss that behaves like squared error for small residuals but is gentler on huge ones, and describe its gradient.

Answer. Use a loss that is quadratic near zero and linear in the tails, the classic construction is the Huber loss: for residual $r$ and threshold $\delta$, take $\frac12 r^2$ when $|r| \le \delta$ and $\delta(|r| - \frac{\delta}{2})$ otherwise. Its gradient is $r$ in the quadratic zone (identical to squared error) and a constant $\pm\delta$ in the tails, so an outlier's pull is capped: it pushes with bounded force instead of quadratically growing force. It is differentiable everywhere, including the seam, unlike $|r|$ at zero. The cost: no closed form, and a new hyperparameter $\delta$ to validate.

Quiz 4 (transfer): derive the ridge update from the plain update

Starting from $w \leftarrow w - \alpha \frac{\partial J}{\partial w}$, derive the update for $\tilde J(w) = J(w) + \lambda w^\top w$ (using the convention where the penalty's gradient is $\lambda w$, absorbing the 2).

Answer. Differentiate the new loss: $\nabla \tilde J = \nabla J + \lambda w$. Substitute into the update: $w \leftarrow w - \alpha(\nabla J + \lambda w) = w - \alpha\lambda w - \alpha \nabla J = (1 - \alpha\lambda)w - \alpha \nabla J$. The regularizer contributes a multiplicative shrink of the weights before the usual data-driven step, which is exactly why ML people call it weight decay.

Quiz 5 (transfer): turn batch GD into stochastic GD

Modify the batch update $w \leftarrow w - \frac{\alpha}{N}\sum_{i=1}^N (w^\top x^{(i)} - t^{(i)})x^{(i)}$ into stochastic gradient descent, and compare the cost per step.

Answer. Replace the average over all $N$ examples with a single randomly drawn example $i$: $w \leftarrow w - \alpha\,(w^\top x^{(i)} - t^{(i)})\,x^{(i)}$, drawing a fresh $i$ each step (in practice, shuffling and sweeping the dataset). Cost per step falls from $O(ND)$ to $O(D)$, a factor of $N$. The single-example gradient is a noisy but unbiased estimate of the full gradient, its expectation over $i$ is exactly the batch gradient, so the path jitters (Fig 9.2's stochastic toggle) but heads to the same valley, and you buy far more steps for the same compute. Mini-batches interpolate between the extremes.

Quiz 6 (transfer): 5 points, degree-4 polynomial, predict the errors

A colleague fits $M = 4$ to $N = 5$ noisy points and reports zero training error, claiming a perfect model. Predict the test error and justify your prediction. What two remedies do you offer?

Answer. Test error will almost certainly be large. Five coefficients can interpolate five points exactly, so zero train error is guaranteed regardless of noise, the model has absorbed $\epsilon$ into its weights, and between the training points the curve oscillates with no data to discipline it. Zero training error here is evidence of memorization, not skill. Remedies, straight from section 10: (1) more data, at $N \gg 5$ the same capacity can no longer thread every point; (2) ridge regularization, penalizing $w^\top w$ tames the ballooning coefficients, with $\lambda$ chosen on a validation split, never on the test set.

That is linear regression, end to end: a model you can read, a loss you derived on screen, two optimizers you executed by hand and by code, and the first honest look at the enemy, overfitting, along with the first weapon against it.
