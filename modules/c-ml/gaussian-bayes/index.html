Gaussian Bayes Models

Every classifier so far has drawn a boundary. Logistic regression drew it with a sigmoid, the SVM drew it with a margin, and neither one ever asked what the data itself looks like. This lecture flips the question. Instead of learning where spam ends and real mail begins, learn what spam looks like, learn what real mail looks like, and when a new email arrives, ask which portrait it resembles. That is generative classification: model each class with a Gaussian, weigh in how common each class is, and let Bayes' rule turn the crank. The payoff is a classifier we never had to optimize, plus a beautiful surprise at the end: the shape of the boundary it implies, curved, straight, or axis-aligned, is controlled entirely by what we assume about the covariance.

0. The hook: stop drawing boundaries

Picture the spam filter problem one more time. Two features per email, one point per email, two colours. Every classifier we have built would now hunt for a boundary: pick a family of separating surfaces, define a loss, run gradient descent, hope it converges somewhere sensible. Here is a different plan. Fit a Gaussian to the spam cloud. Fit a Gaussian to the real-mail cloud. Note that, say, 30% of email is spam. Done, that is the whole training procedure, and it is two closed-form fits from last lecture. When a new email arrives, evaluate both Gaussians at its feature vector, multiply each by how common its class is, and report the class with the bigger product.

Where does the boundary come from? We never asked for one, but one appears anyway: it is the set of points where the two products tie. And here is the part that makes this lecture worth its slot in the course. The shape of that implied boundary is not something we tune. It falls out of what we assume about each class's covariance. 1. Discriminative vs generative

Both families solve the same prediction problem, but they learn different objects. A discriminative classifier learns the prediction directly: either the conditional probability $p(y \mid x)$, the way logistic regression and softmax do, or a class score and a boundary, the way the SVM, the perceptron, and the least-squares classifier do. It never forms an opinion about the inputs themselves. Ask logistic regression "what does a typical spam email look like?" and it has nothing to say; it only knows how to separate.

A generative classifier models how each class's data is distributed. It learns the class-likelihood $p(x \mid y)$, what class $y$'s inputs look like, together with the class prior $p(y)$, how common class $y$ is. Together those are exactly the joint distribution, $p(x, y) = p(x \mid y)\, p(y)$, which is why the family is called generative: a model of the joint could in principle generate new labelled data. Prediction is then recovered, not learned: $p(y \mid x)$ comes from Bayes' rule, which is section 2's whole job.

Fig 1.1, the same two-class data through both philosophies. The discriminative view learns one object, a boundary, and models nothing else; the generative view learns four objects, a Gaussian and a prior per class, and its overlap implies a boundary for free (dashed). Toggle between them and compare what each side would write down after training, listed under the plot and computed live from the data.

Why would anyone take the indirect route? Because the generative side gets to reuse everything the MLE lecture built. Each class-likelihood is fit on its own class's data by maximum likelihood, in closed form, no gradient descent, no learning rate. The prior is a counting exercise. And the model is interpretable: after training you can literally read off what the model thinks each class looks like. The price, and it is a real price, is that we must assume a distribution for $p(x \mid y)$, and this lecture's choice of Gaussian is an assumption the data may or may not honour. Hold that thought until the method card.

2. The Bayes classifier

Suppose the modeling is done: we hold a class-likelihood $p(x \mid C = k)$ for every class $k$ and a prior $p(C = k)$. A new input $x_{\text{new}}$ arrives. What we want is the posterior probability of each class given the input, and Bayes' rule, the same identity that powered MAP estimation last lecture, delivers it:

$$ p(C = k \mid x_{\text{new}}) = \frac{p(x_{\text{new}} \mid C = k)\, p(C = k)}{p(x_{\text{new}})}, \qquad \text{posterior} = \frac{\text{class-likelihood} \times \text{prior}}{\text{evidence}}. $$

Read it as a tug of war between three characters:

🔍
Class-likelihood $p(x \mid C = k)$
Does this input look like your class? The portrait each class painted during training, evaluated at the query.
⚖️
Prior $p(C = k)$
How common is your class in the first place? A rare class needs a strong resemblance to win.
🧾
Evidence $p(x_{\text{new}})$
How probable is this input overall, under any class? One number, shared by every class's denominator.

The posterior is likelihood times prior, normalized by the evidence. Now the key observation: when we compare classes, the evidence is the same number in every denominator. It cannot change which class wins. So the decision rule drops it:

$$ y(x) = \arg\max_k \; p(x \mid C = k)\, p(C = k). $$

This is the Bayes classifier, and it carries a guarantee the boundary-hunting methods never had: predicting the class with the highest posterior minimizes the expected number of mistakes. If the model of the data is right, no classifier does better on average. That is the prize for modeling $p(x \mid y)$ instead of attacking the boundary directly.

Worked by hand: the diabetes example

Screen for diabetes from a white-blood-cell count $x$. Assume the prior $p(C = 1) = 0.3$ (30% of the screened population is diabetic), and suppose the per-class MLE fits from section 3 came out as healthy $\mathcal{N}(50, 4^2)$ and diabetic $\mathcal{N}(42, 6^2)$. A patient shows $x = 48$. Evaluate both class-likelihoods:

p(48 | C=0) = N(48; 50, 16) = 0.0880    p(48 | C=1) = N(48; 42, 36) = 0.0403

Multiply by the priors and normalize. The evidence is just the sum of the two products:

p(C=0) · p(48|C=0) = 0.7 × 0.0880 = 0.0616
p(C=1) · p(48|C=1) = 0.3 × 0.0403 = 0.0121
p(C=1 | 48) = 0.0121 / (0.0616 + 0.0121) = 0.164

Posterior 16.4% diabetic, so the Bayes classifier says healthy. Notice both forces at work: $x = 48$ sits closer to the healthy mean, and the prior already leaned 70/30 against diabetes. 3. Fitting Gaussians by MLE

The Bayes classifier is a rule waiting for ingredients. Where do the class-likelihoods come from? This lecture's answer: assume each class's inputs are Gaussian, each class with its own parameters, and estimate those parameters from that class's training points. In one dimension the class-conditional density is

$$ p(x \mid C) = \frac{1}{\sqrt{2\pi}\,\sigma_C}\exp\!\left(-\frac{(x - \mu_C)^2}{2\sigma_C^2}\right), $$

and we already know from last lecture how to fit it: write the i.i.d. log-likelihood of the class's points, set the derivatives with respect to $\mu$ and $\sigma^2$ to zero, and closed forms drop out. The only new wrinkle is bookkeeping: for class $C_k$, sum over the points whose label $t^{(i)}$ is $C_k$, and nobody else's:

$$ \hat{\mu}_{ML} = \frac{1}{N}\sum_{i:\, t^{(i)} = C_k} x^{(i)}, \qquad \hat{\sigma}^2_{ML} = \frac{1}{N}\sum_{i:\, t^{(i)} = C_k} \big(x^{(i)} - \hat{\mu}_{ML}\big)^2. $$

The sample mean and the sample variance of the class. No optimizer, no iterations. "Fit each class by MLE" is a phrase worth making literal, so do it yourself:

Fig 3.1, fit a Gaussian by MLE, literally. One class's points sit on the number line. First try to fit by eye: slide $\mu$ and $\sigma$ and watch the log-likelihood of the data respond. Then press Fit by MLE and the closed-form $\hat{\mu}, \hat{\sigma}$ snap into place, with the numbers shown; the log-likelihood readout confirms no hand-tuned curve beats them. Worked by hand: one class, five points

Class points $\{4.2,\; 5.1,\; 4.7,\; 5.6,\; 4.4\}$. The MLE mean is the sample mean:

μ̂ = (4.2 + 5.1 + 4.7 + 5.6 + 4.4) / 5 = 24.0 / 5 = 4.8

Deviations from 4.8 are $-0.6, 0.3, -0.1, 0.8, -0.4$; square, average:

σ̂² = (0.36 + 0.09 + 0.01 + 0.64 + 0.16) / 5 = 1.26 / 5 = 0.252    σ̂ = 0.502

That pair $(\hat{\mu}, \hat{\sigma}^2) = (4.8, 0.252)$ defines this class's likelihood curve, ready to be multiplied by a prior in the Bayes rule. Repeat per class and the classifier is trained.

From a number line to $d$ dimensions

Real inputs are vectors, so each class needs a Gaussian over $\mathbb{R}^d$. Two objects replace the two scalars: a mean vector, and a covariance matrix $\Sigma$ that encodes each feature's variance on its diagonal and every pairwise covariance off it. The MLE estimates are the same recipe, promoted to vectors, over the class's $N$ points:

$$ \hat{\mu}_{ML} = \frac{1}{N}\sum_{i=1}^{N} x^{(i)}, \qquad \hat{\Sigma}_{ML} = \frac{1}{N}\sum_{i=1}^{N} \big(x^{(i)} - \hat{\mu}_{ML}\big)\big(x^{(i)} - \hat{\mu}_{ML}\big)^\top. $$

How many numbers is that? Count them, because the count becomes the plot of sections 6 and 7. In 1-D a Gaussian costs 2 parameters, a mean and a variance. In $d$ dimensions:

$$ \underbrace{d}_{\text{means}} \;+\; \underbrace{d}_{\text{variances}} \;+\; \underbrace{\tfrac{d^2 - d}{2}}_{\text{covariances}} \;=\; O(d^2), $$

where the covariance term is halved because $\Sigma$ is symmetric: the covariance of feature 3 with feature 7 is the covariance of feature 7 with feature 3, counted once. At $d = 10$ that is $10 + 10 + 45 = 65$ parameters per class. Quadratic growth is a slow-burning problem; sections 5 and 6 watch it detonate.

Check: why does each class get only its own points?

The MLE sums range over $i$ with $t^{(i)} = C_k$. Why not use all the data for every class, there is more of it?

Answer. Because the object being estimated is $p(x \mid C = k)$: the distribution of inputs given that the class is $k$. Points from other classes are samples from other conditionals, and mixing them in would estimate the marginal $p(x)$ instead, blurring every class portrait toward the global average. The likelihood factorizes by class, so maximizing it splits into $k$ independent fits, each on its own subset. That is also the practical charm of generative training: each class's fit is a separate closed-form computation, and adding a new class later does not disturb the others. The other classes do enter the classifier, but through the comparison in the argmax, not through each other's fits.

4. The multivariate Gaussian

Before stacking Gaussians into a classifier, get a feel for the object itself. The density over $\mathbb{R}^d$ is

$$ p(x) = \frac{1}{(2\pi)^{d/2}\,|\Sigma|^{1/2}} \exp\!\left(-\tfrac{1}{2}(x - \mu)^\top \Sigma^{-1}(x - \mu)\right). $$

Squint and the 1-D formula is still visible: a normalizer out front, and an exponential of a negative squared distance. The distance is the new part. $(x - \mu)^\top \Sigma^{-1} (x - \mu)$ measures how far $x$ is from the mean in units of the covariance: directions where the data spreads widely count for little, directions where the data is tight count for a lot. Set that quadratic to a constant and you get the density's contour, an ellipse, and the covariance is the ellipse's shape dial:

  • Isotropic, $\Sigma = \sigma^2 I$: every direction identical, circular contours.
  • Axis-aligned, unequal diagonal entries: an ellipse stretched along the coordinate axes, features uncorrelated but differently spread.
  • Correlated, nonzero off-diagonal entries: the ellipse tilts, and the sign of the covariance sets the tilt direction, positive leaning up-right, negative leaning down-right.

Fig 4.1, the covariance-shape explorer, the intuition anchor for everything that follows. The density and its 1σ/2σ contour ellipses are computed live from the $\Sigma$ you dial in with the two variance sliders and the correlation slider; the matrix and its determinant update alongside. Walk the presets: isotropic (circle), axis-aligned (upright ellipse), and correlated (tilted ellipse, sign flips the tilt).

5. The Gaussian Bayes classifier (GDA)

Now assemble the machine. A $k$-class Gaussian Bayes classifier, also called Gaussian discriminant analysis (GDA), has two parts: a categorical prior $p(C = k)$ over the classes, and a Gaussian class-likelihood $\mathcal{N}(\mu_k, \Sigma_k)$ per class. Training is section 3 run $k$ times: fit each class's $\mu_k, \Sigma_k$ by MLE on that class's points, and set the priors from the class frequencies. Prediction is section 2: report the class with the biggest posterior. In log form, which is how any implementation actually computes it, the posterior of class $k$ is

$$ \log p(C = k \mid x) = -\tfrac{d}{2}\log(2\pi) - \tfrac{1}{2}\log|\Sigma_k| - \tfrac{1}{2}(x - \mu_k)^\top \Sigma_k^{-1}(x - \mu_k) + \log p(C = k) - \log p(x), $$

and the decision is $y(x) = \arg\max_k p(C = k \mid x)$. Read the terms as a scorecard: a constant everyone shares, a penalty for having a spread-out class (big $|\Sigma_k|$), the covariance-scaled distance from the class mean, a bonus for being a common class, and the evidence term, which is identical across classes and gets dropped from the argmax exactly as before.

Fig 5.1, a full GDA classifier in 2-D, the second signature figure. Three classes, each fitted by MLE (mean crosses, 1σ/2σ ellipses), with the decision regions and boundaries computed live from the log-posteriors. Drag the query point (or use arrow keys) to read all three posteriors and the verdict. The covariance-mode toggle re-fits the same data three ways, full per-class, shared, and shared diagonal, morphing the boundaries from curved (QDA) to straight (LDA) to axis-aligned-portrait straight (Gaussian Naive Bayes), with the live Gaussian parameter count for each mode.

The parameter count in that figure deserves a hard stare. Each full covariance costs $O(d^2)$ numbers, and GDA fits one per class: $O(k \cdot d^2)$ parameters in total. In 2-D that is charming. In 1000-D, one class's covariance alone is roughly half a million numbers, all of which need data to pin down, and the estimate is only trustworthy when the class has far more points than parameters. GDA in high dimensions is data-intensive, and that pressure is exactly what section 6 relieves.

The code

The whole classifier is four short functions. Note that gda_predict drops the evidence and works in logs, so products of tiny densities never underflow: 

import numpy as np

def fit_gaussian(X_class):
    mu = X_class.mean(axis=0)
    D = X_class - mu
    Sigma = D.T @ D / len(X_class)        # MLE: divide by N
    return mu, Sigma

def gaussian_pdf(x, mu, Sigma):
    d = len(mu)
    diff = x - mu
    quad = diff @ np.linalg.inv(Sigma) @ diff
    norm = (2 * np.pi) ** (d / 2) * np.linalg.det(Sigma) ** 0.5
    return np.exp(-0.5 * quad) / norm

def gda_fit(X, t, k):
    classes = []
    for c in range(k):
        Xc = X[t == c]
        mu, Sigma = fit_gaussian(Xc)
        classes.append((mu, Sigma, len(Xc) / len(X)))   # prior = frequency
    return classes

def gda_predict(x, classes):
    scores = [np.log(prior) + np.log(gaussian_pdf(x, mu, Sigma))
              for mu, Sigma, prior in classes]
    return int(np.argmax(scores))         # evidence not needed

Check: why fit in high dimensions is the hard part

Training GDA is closed-form, so what exactly makes it "data-intensive" at $O(k \cdot d^2)$ parameters? The formula computes instantly either way.

Answer. The cost is statistical, not computational. Every entry of $\hat{\Sigma}_k$ is an average over class $k$'s points, and an average over too few points is noise wearing a suit. With $d = 100$, one class's covariance holds $100 + 4950 = 5050$ distinct numbers; estimate those from 200 points and most entries are guesses, the fitted ellipsoid degenerates, and $\Sigma_k^{-1}$, which the log-posterior needs, becomes unstable or outright singular. That is why the section 7 menu exists: sharing the covariance pools every class's points into one estimate, and going diagonal cuts the count to $O(d)$. The covariance constraint is not a modeling nicety, it is the knob that matches the parameter count to the data you actually have.

Check your understanding

In gda_predict, the score is log(prior) + log(gaussian_pdf(...)) and the evidence never appears. A teammate "fixes" it by dividing every score's probability by $p(x)$ before the argmax. What changes?

Right. In log space the evidence is a common additive shift, and an argmax is blind to common shifts. That is the computational face of "the evidence is constant across classes". Compute it only when you want the posterior as an actual probability, as Fig 5.1's readout does by normalizing.
Normalizing does produce genuine posteriors, which is useful for reporting confidence, but the ranking of classes, and therefore every prediction and the accuracy, is untouched.
$p(x)$ is perfectly computable: sum the likelihood-times-prior products over the classes. It is skipped in the argmax because it is unnecessary, not because it is unavailable.

6. Naive Bayes

Back to spam, and this time take the features seriously. Represent an email by a binary bag-of-words vector $x \in \{0, 1\}^D$: one bit per vocabulary word, 1 if the email contains it. With a vocabulary of $D$ words there are $2^D$ possible vectors, and an arbitrary class-likelihood $p(x \mid C = k)$ must assign a probability to every one of them: about $2^D - 1$ free parameters per class. At $D = 30$ that is already over a billion numbers; a realistic vocabulary makes the count larger than any dataset that will ever exist. Modeling the joint distribution of the features is intractable head on.

Naive Bayes buys tractability with one aggressive assumption: the features are conditionally independent given the class. Once you know an email is spam, knowing it contains "winner" tells you nothing extra about whether it contains "free". Then the joint factorizes into per-feature pieces:

$$ p(c, x_1, \dots, x_D) = p(c)\prod_{d=1}^{D} p(x_d \mid c), $$

and the price list collapses: instead of $2^{D+1}$ numbers for the full joint over class and features, we need $D + 1$ Bernoulli parameters, one prior plus one per-word probability per class. The assumption is false, obviously, "free" and "winner" travel together in real spam, which is why the model is called naive. But false assumptions can still buy useful classifiers, and this one buys a factor-of-$2^D$ discount. Watch the two price tags diverge:

Fig 6.1, the independence assumption's payoff. Slide the vocabulary size $D$: the full joint needs about $2^D - 1$ parameters per class (log scale, note the axis), while Naive Bayes needs $D + 1$. Both counts are computed exactly and printed; the reference lines mark the size of real datasets, which the full joint outgrows before $D$ reaches 40.

The decision rule keeps the Bayes shape, with the product replacing the joint likelihood:

$$ y(x) = \arg\max_k \; p(C = k)\prod_{d=1}^{D} p(x_d \mid C = k). $$
Worked by hand: a three-word spam filter

Vocabulary {free, meeting, winner}, priors $p(\text{spam}) = p(\text{ham}) = 0.5$, and per-word conditionals estimated from data:

p(free|spam)=0.8  p(meeting|spam)=0.1  p(winner|spam)=0.6
p(free|ham) =0.2  p(meeting|ham) =0.7  p(winner|ham) =0.05

An email contains "free" and "winner" but not "meeting": $x = (1, 0, 1)$. Score each class, remembering an absent word contributes one minus its probability:

spam: 0.5 × 0.8 × (1−0.1) × 0.6 = 0.216
ham:  0.5 × 0.2 × (1−0.7) × 0.05 = 0.0015
p(spam | x) = 0.216 / (0.216 + 0.0015) = 0.993

Four multiplications per class, seven parameters total, and a 99.3% posterior. That is the whole model.

Gaussian Naive Bayes: independence as a diagonal

What does the independence assumption look like back in the Gaussian world? A multivariate Gaussian's features are independent exactly when its covariances are zero, so Gaussian Naive Bayes is the Gaussian Bayes classifier with a diagonal covariance, $\Sigma = \operatorname{diag}(\sigma_1^2, \dots, \sigma_D^2)$. The multivariate class-likelihood then factorizes into a product of 1-D Gaussians, one per feature:

$$ p(x \mid C = k) = \prod_{d=1}^{D} \mathcal{N}\!\big(x_d;\; \mu_{dk},\, \sigma_{dk}^2\big). $$

Same trade as the Bernoulli case: the full covariance's $O(d^2)$ parameters drop to $O(d)$ diagonal entries per class, at the cost of declaring every feature pair uncorrelated within a class. Geometrically, every class portrait is forced to be an axis-aligned ellipse from Fig 4.1's middle preset. Keep that picture; it becomes a boundary shape in the next section.

In code, the change from gda_predict is one line of modeling: score each feature with its own 1-D Gaussian and sum the logs, which is the log of the product in the decision rule: 

def naive_bayes_predict(x, classes):
    # classes: per class, (mu[d], var[d], prior); features independent given C
    scores = []
    for mu, var, prior in classes:
        log_lik = sum(-0.5 * np.log(2 * np.pi * var[d])
                      - (x[d] - mu[d]) ** 2 / (2 * var[d])
                      for d in range(len(x)))          # log Π = Σ log
        scores.append(np.log(prior) + log_lik)
    return int(np.argmax(scores))

Ten days of records, two features (Outlook, Temp), and whether a match was played. Reworded from the assignment's tennis exercise, with fresh numbers:

Play=yes (6): (Sunny,Cool) (Sunny,Mild) (Overcast,Hot) (Overcast,Cool) (Rain,Mild) (Rain,Cool)
Play=no  (4): (Sunny,Hot) (Sunny,Hot) (Sunny,Mild) (Rain,Cool)

Answer. Priors from frequencies: $p(\text{yes}) = 0.6$, $p(\text{no}) = 0.4$. Conditionals by counting within each class: $p(\text{Sunny} \mid \text{yes}) = 2/6$, $p(\text{Cool} \mid \text{yes}) = 3/6$, $p(\text{Sunny} \mid \text{no}) = 3/4$, $p(\text{Cool} \mid \text{no}) = 1/4$. Scores:

Worth noticing how close the call is: Sunny leans hard toward no (3 of the 4 no-days were sunny), Cool leans toward yes, and the prior tips the balance. Every number came from counting, which is Naive Bayes's entire training procedure for categorical features.

Check your understanding

You multiply one feature by 1000 (say, metres become millimetres) and refit. What happens to Gaussian Naive Bayes's predictions, and why is this different from k-NN?

That is the failure mode of distance-based models, not of Naive Bayes. Each feature here gets its own 1-D Gaussian whose parameters are re-estimated on the rescaled data, so the feature's standardized distance from the class mean is what it always was.
Right. Variances can be any positive number; a Gaussian's density can even exceed one, since it is a density, not a probability. Nothing crashes.

7. Decision boundaries: QDA, LDA, Gaussian Naive Bayes

We never optimized a boundary in this whole lecture, but every Bayes classifier implies one: the set of inputs where two classes' posteriors tie. For $k = 2$,

$$ p(C = 1 \mid x) = p(C = 0 \mid x) \;\Rightarrow\; p(x \mid C = 1)\,p(C = 1) = p(x \mid C = 0)\,p(C = 0), $$

where the evidence cancelled from both sides, as usual. What does this set look like when the likelihoods are Gaussian? Take logs and expand in 1-D. Each side contributes $-\tfrac{(x - \mu_k)^2}{2\sigma_k^2} - \log\sigma_k + \log p(C = k)$, and collecting powers of $x$ leaves

$$ a x^2 + b x + c = 0, \qquad a = \frac{1}{2\sigma_0^2} - \frac{1}{2\sigma_1^2}, $$

a quadratic equation whenever $\sigma_1 \neq \sigma_0$, with up to two roots: the narrow class can carve an island out of the middle of the wide class's territory. And if the variances are equal? Then $a = 0$, the quadratic terms cancel, and the boundary is a single linear threshold. Watch the cancellation happen:

Fig 7.1, the equal-posterior condition becoming a quadratic. The coefficients $a, b, c$ are computed live from the two Gaussians and priors, the roots are solved and drawn as boundary lines, and the coloured band along the top shows each class's winning territory, two boundary points when the variances differ. Drag the variance sliders toward each other, or press Equalize, and watch $a \to 0$: the quadratic degenerates and exactly one linear boundary survives.

The same expansion works in $d$ dimensions. Equating the two log-posteriors and dropping shared constants gives

$$ x^\top \Sigma_1^{-1} x - 2\mu_1^\top \Sigma_1^{-1} x = x^\top \Sigma_2^{-1} x - 2\mu_2^\top \Sigma_2^{-1} x + \text{const}, $$

a quadratic function of $x$: in 2-D the boundary is a conic, an ellipse, parabola, or hyperbola. But look at the quadratic terms. If the two classes share one covariance, $\Sigma_1 = \Sigma_2$, then $x^\top \Sigma^{-1} x$ appears identically on both sides and cancels, and everything left is linear in $x$: a straight boundary, from a model that never aimed for one. The covariance assumption is the boundary dial:

Covariance structure → boundary geometry

Not shared, diagonalGaussian Naive Bayes: linear boundary, axis-aligned class portraits, $O(k \cdot d)$ parameters.
Shared, arbitraryLDA (linear discriminant analysis): linear boundary, $O(d^2)$ parameters.

Two vocabulary notes to lock in, straight from the mini-summary. The Gaussian Bayes classifier in its shared-covariance form, $\arg\max_k p(C = k)\, p(x \mid C = k)$ with one arbitrary $\Sigma$ for all classes, is the LDA case: linear boundaries. The Gaussian Naive Bayes classifier is the same rule with a diagonal covariance, so its likelihood factorizes over dimensions. Everything in this lecture is one classifier wearing different covariance constraints.

Check your understanding

Two classes in $d = 20$ dimensions. Model A gives each class its own full covariance; model B shares one full covariance between them. What are the boundary shapes and Gaussian parameter counts (means plus covariances)?

B's boundary is not quadratic: sharing the covariance makes the quadratic terms identical on both sides of the equal-posterior equation, and they cancel. That cancellation is the whole LDA story.
You have the two models swapped. Per-class covariances (A) are what keep the quadratic terms alive; sharing (B) cancels them into a linear boundary.
Right. A covariance in 20-D costs $20 + (400 - 20)/2 = 210$ numbers, plus 20 means per class: A pays for two of everything (460), B pays for two means but one covariance (250), and B's reward for the constraint is a straight boundary.

8. Summary and method card

One idea carried the whole lecture: model what inputs from each class look like, then use Bayes' rule to decide which class most likely generated a new input. The Bayes classifier is the decision rule, $\arg\max_k p(x \mid C = k)\, p(C = k)$, with the evidence dropped because it cannot change the winner. MLE from last lecture supplies the ingredients in closed form: a mean and a variance per class in 1-D, a mean vector and a covariance matrix in $d$ dimensions. The covariance is both the model's expressive power, tilting and stretching each class's portrait, and its appetite, $O(d^2)$ parameters per class. Naive Bayes tames the appetite by assuming conditional independence, collapsing $2^D$-scale joints to $D + 1$ parameters, and in the Gaussian world that assumption is simply a diagonal covariance. And the boundary geometry is bookkeeping on the same quadratic: per-class covariances keep the quadratic terms alive (QDA), a shared covariance cancels them (LDA, linear), and diagonal restrictions buy axis-aligned portraits at $O(d)$ cost. If you want the full story in print, this is Bishop's Pattern Recognition and Machine Learning territory, with the decision-theory framing in Russell's Artificial Intelligence: A Modern Approach.

9. End-of-lesson quiz

Two quick checks, then three transfer questions that ask you to decide and justify, not recall. Attempt each before expanding the answer.

Quiz 1

What exactly does a generative classifier learn that a discriminative one does not, and how does it predict?

Learning $p(y \mid x)$ directly is the definition of the discriminative route. The generative route models the inputs per class and recovers the conditional afterwards.
A boundary is what discriminative score-based methods learn. The generative model never optimizes a boundary; one merely emerges where posteriors tie.
Right. Model the data per class, count the priors, and Bayes' rule turns the crank: $\arg\max_k p(x \mid C = k)\, p(C = k)$, evidence dropped.
Quiz 2

A two-class Gaussian Bayes classifier is fit with one shared, arbitrary covariance matrix. A colleague expects a curved boundary "because Gaussians are curvy". What does the model actually produce?

Only when each class keeps its own covariance (QDA). Sharing makes the quadratic terms equal on both sides of the tie equation, and equal terms cancel.
Right. The curviness of each density is real, but boundaries come from differences of log-densities, and sharing the covariance wipes out the quadratic difference. Fig 7.2's slider is exactly this cancellation in motion.
The class means still differ, and the linear term they generate is precisely the boundary. Shared shape does not mean shared location.
Quiz 3 (transfer): generative or discriminative, and defend it

Two projects land on your desk. Project one: classify emails with 40 labelled examples, and the product team also wants to flag emails that look like nothing seen before. Project two: classify images of handwritten digits with two million labelled examples, maximizing raw accuracy. Pick a family for each and justify it.

Answer. Project one wants generative, project two wants discriminative. With 40 examples, closed-form MLE fits of a heavily constrained generative model (Naive Bayes, or Gaussian Naive Bayes with its $O(d)$ parameters) are estimable where a flexible discriminative model would overfit, the priors let us encode how rare spam is without needing data to say so, and, decisively, a generative model owns a density: an email with tiny $p(x \mid C = k)$ under every class looks like nothing the model has seen, which is the flag the product team asked for. A discriminative model has no notion of "looks like nothing", it only knows which side of a boundary a point falls on. Project two reverses every consideration: with two million examples the data can pin down a flexible boundary directly, and the generative route's distributional assumptions (are digit images really Gaussian per class?) become the accuracy bottleneck. Learn $p(y \mid x)$ or the boundary directly and spend the data on it. The general rule: generative models earn their keep when data is scarce, priors matter, or you need the input distribution itself; discriminative models win when data is plentiful and the only question is the label.

Quiz 4 (transfer): LDA's line meets logistic regression's line

LDA (shared covariance) produces a linear decision boundary. So does logistic regression. Same boundary family, so are they the same model? Where do they differ, and when would each win?

Answer. Same family of boundaries, different routes to choosing one, and the routes matter. Work out LDA's log-posterior ratio: with $\Sigma_1 = \Sigma_0$, $\log \frac{p(C=1 \mid x)}{p(C=0 \mid x)}$ is linear in $x$, so the posterior has exactly the form $\sigma(w^\top x + b)$: LDA is secretly a sigmoid over a linear score, the very shape logistic regression assumes from the start. The difference is what gets estimated. LDA reaches $w$ indirectly, by fitting means, a shared covariance, and priors to the whole input distribution by MLE; logistic regression fits $w$ directly by maximizing the conditional likelihood of the labels. When the Gaussian, shared-covariance story is roughly true, LDA squeezes more out of small samples, because it uses every point's position, not just its side of the boundary, to pin down the geometry. When the story is false, say the classes are skewed or heavy-tailed, LDA's boundary is bent by its wrong assumptions, while logistic regression, which never assumed anything about $p(x)$, degrades more gracefully. Assumptions pay when they are true and charge when they are false, which is this lecture's method card in one sentence.

Quiz 5 (transfer): one Gaussian per class is not enough

A class's data forms two separate clumps (say, fraudulent transactions split into "stolen card" and "fake merchant" patterns). One Gaussian per class fits poorly. Sketch the fix, and explain how the same idea gives an anomaly detector.

Answer. Peek ahead: replace the single Gaussian with a mixture of Gaussians, $p(x \mid C) = \sum_m \pi_m\, \mathcal{N}(x; \mu_m, \Sigma_m)$, weights $\pi_m$ summing to one. Each component covers one clump, and the class-likelihood becomes flexible enough for multi-modal classes while every downstream piece of this lecture, priors, Bayes' rule, the argmax, is untouched. The fitting is the one genuinely new ingredient: no closed form exists once components must share the points, which is what the EM algorithm handles when the course reaches Gaussian Mixture Models. The anomaly detector comes free, exactly because the model is generative: a fitted mixture assigns every point a log-likelihood $\log p(x)$, so score incoming points and flag the ones far below the training data's typical range; they resemble no component, no matter the label. You can even sample from the mixture to sanity-check what the model believes the data looks like, a move no boundary-only model can offer. This is the source's flagged peek ahead at GMMs; the machinery arrives in a later lecture.

That is generative classification. We never drew a boundary, and got a better-principled one than the boundary hunters: model each class, count the priors, and let Bayes' rule decide, with the covariance assumption as a single dial that trades parameters for boundary shape, QDA to LDA to Naive Bayes. The deeper habit to keep is the modeling reflex itself: when a problem looks hard head on, ask what process generated the data, model that, and let probability do the deciding.
