Linear Classification

Last lecture we learned to predict numbers. This lecture we learn to make decisions. The move is smaller than it sounds: keep the exact same linear score from regression, then chop it at a threshold, and a number becomes a verdict. That one chop creates everything new here, decision boundaries, the two kinds of mistakes, precision and recall, and the perceptron, the 1958 algorithm that learns a boundary by being corrected one error at a time. Every concept gets an interactive figure with real computed numbers.

0. From predictions to decisions

Think about the systems that actually act on you. A bank does not tell you "your creditworthiness is 0.73"; it approves the loan or it rejects it. A photo app does not report "dogness: 0.9"; it files the picture under dog or not dog. A fraud system does not email you a suspicion level; it blocks the transaction or lets it through. Under the hood, every one of these systems still computes a continuous number, a score: risk, fraud, churn, dogness. The decision comes from one extra step. Compare the score to a cutoff, and act.

That pipeline, score → threshold → class label, is the whole subject of this lecture. Classification means assigning each input to one of a finite set of labels: two labels makes the problem binary, more than two makes it multi-class. Regression predicted continuous outputs; classification predicts discrete ones. And here is the good news: we reuse the entire regression machinery, collect data, pick a model, pick a loss, optimize, regularize. Only the target changed. Feel the pipeline first, before any math:

Fig 0.1, the score-to-decision pipeline, live. Drag the applicant along the feature axis. The linear score $s(x) = w_0 + w_1 x_1$ is computed for real, compared against the threshold at zero, and the label flips the instant the score crosses it. One continuous number, one cutoff, one decision.

Notice what the chop forces on us. The moment a number becomes a decision, two new questions appear that regression never had to answer. Where exactly does the flip happen? That is the decision boundary, section 2. And when the decision is wrong, how wrong is it, and does the direction of the error matter? That is the cost of mistakes, sections 3 and 4. Then we learn the boundary from data (section 5) and handle more than two classes (section 6).

1. Classification as regression

We already own a machine that turns features into a number. It is the linear model from last lecture:

$$ f(w, x) = w_0 + w^\top x = w_0 + \sum_{i=1}^{d} w_i x_i $$

Each feature $x_i$ contributes to the total in proportion to its weight $w_i$, and $w_0$ shifts the whole thing up or down. A linear classifier is exactly this: a weighted scoring rule. Income adds points, missed payments subtract points, and the final tally decides. Simple, fast, and you can read the model's reasoning straight off the weights.

So here is the cheapest possible classifier, and it genuinely works. Encode the two classes as numeric targets $t \in \{-1, +1\}$. Fit the linear model to those targets with the same least-squares loss we minimized last lecture:

$$ J_{\text{square}}(w) = \frac{1}{N} \sum_{n=1}^{N} \left( w^\top x^{(n)} - t^{(n)} \right)^2 $$

The fitted line tries to output values near $+1$ over the positive examples and near $-1$ over the negative ones. It will never be exactly right, a line cannot equal two constants at once, but we do not need it to be. We only need its sign. Threshold the fitted score at zero and read off a class. That is the decision rule:

$$ y(x) = \operatorname{sign}\!\left( w_0 + w^\top x \right) = \begin{cases} +1 & \text{if } w_0 + w^\top x \ge 0 \\[2pt] -1 & \text{otherwise}\end{cases} $$

In NumPy the whole prediction step is one line for the entire dataset:

# X has a leading column of ones, so w[0] is the intercept w0
def predict(X, w):
    return np.sign(X @ w)     # one score per row, chopped to -1 / +1

Watch the trick happen, and then watch it misbehave. The figure below fits a real least-squares line to 1-D two-class data and thresholds it at zero. The crossing point becomes the boundary, and the two sides of it become the two predicted classes. Then press the button that adds a few extreme but perfectly valid positive examples far to the right:

Fig 1.1, regression as a classifier. The orange line is the genuine least-squares fit to targets $t = \pm 1$; where it crosses zero becomes the decision boundary, and the shaded regions are the two predicted classes. Add the distant positive points: the squared loss drags the line toward them, the crossing slides right, and previously correct points get misclassified. Squared loss punishes the model for being too confidently right, which is the first hint that classification wants its own loss.

Keep that failure in your pocket. Least squares cares about the distance between the score and $\pm 1$, but classification only cares about the side. Points far into their own region are the easiest cases in the world, yet squared loss treats them as huge errors and warps the boundary to appease them. Fixing this properly is next lecture's job. For now the takeaway is positive: threshold a regression and you have a working classifier, plus a precise geometric object to study, the place where the decision flips.

2. Decision boundaries

The decision boundary is the set of inputs where the classifier switches classes, which for our rule is exactly where the score is zero:

$$ w_0 + w^\top x = 0 $$

On one side the score is positive and the model says $+1$; on the other it is negative and the model says $-1$. Each side is called a half-space. The boundary itself is the same equation in every dimension, but its shape grows with $d$: a single point in 1-D, a line in 2-D, a plane in 3-D, and a hyperplane beyond that.

Worked by hand: the 1-D boundary

Take $w_0 = -1$ and $w_1 = 2$, so the score is $s(x_1) = -1 + 2x_1$. Set it to zero and solve:

$$ -1 + 2x_1 = 0 \;\;\Rightarrow\;\; x_1 = -\frac{w_0}{w_1} = \frac{1}{2} $$

The boundary is the single point $x_1 = 0.5$. Check both sides with real numbers. At $x_1 = 2$: $s = -1 + 4 = 3 \ge 0$, predict $+1$. At $x_1 = 0$: $s = -1 < 0$, predict $-1$. Because $w_1 > 0$, the score grows to the right, so the positive half-line is the right side. Flip the sign of $w_1$ and the sides swap while the boundary point moves to $-w_0/w_1$.

In 2-D the geometry gets richer and more useful. The weight vector $w = (w_1, w_2)$ is perpendicular to the boundary line and points into the positive half-space; it is called the normal vector. The intercept $w_0$ slides the line back and forth without rotating it. Every linear classifier you will ever meet, this lecture's perceptron, next lecture's logistic regression, later the SVM, is at heart a choice of this one line. Build the intuition with your hands:

Fig 2.1, the decision boundary in 1-D, 2-D, and 3-D. In 2-D, drag the arrowhead to rotate the normal vector $w$ (the line stays perpendicular to it), drag anywhere else on the plot to slide the boundary through that point, or use the sliders; the shaded half-spaces, the live equation, and the count of correctly classified points all update from the real score. The 1-D tab shows the same equation collapsing to the worked point $x_1 = -w_0/w_1$, and the 3-D tab shows the boundary becoming a plane.

Two honest remarks before moving on. First, interpretability: a linear classifier's verdict always decomposes into per-feature contributions $w_i x_i$, which is why regulated industries love it. Second, the obvious limitation: all of this assumes a straight boundary is appropriate for the data. Section 5 shows a four-point dataset where no straight line works at all.

3. The cost of mistakes

A classifier's output is right or wrong, so the most direct way to score it is to count. That is the zero/one loss: pay nothing for a correct label, pay one for any error.

$$ L_{0\text{-}1}(y(x), t) = \begin{cases} 0 & \text{if } y(x) = t \\[2pt] 1 & \text{if } y(x) \neq t \end{cases} $$

It is the honest count of mistakes, and it has two serious limitations. The first is mathematical: it is not differentiable, it is flat almost everywhere with sudden jumps, so the gradient machinery from last lecture gets no signal from it. Hold that thought for section 5 and for logistic regression. The second limitation is the one this section is about: zero/one loss treats all errors as equal, and in the real world they are not.

With two classes there are exactly two ways to be wrong, and they have names. A false positive is crying wolf: the truth is $t = -1$ but the model says $y = +1$. A false negative is a miss: the truth is $t = +1$ but the model says $y = -1$. Now attach a scenario. A diabetes screen flags patients for a follow-up test. A false positive means one healthy person gets an unnecessary follow-up, annoying and a little costly. A false negative means a diseased patient walks away undiagnosed. These are not the same size of bad. The same asymmetry shows up everywhere decisions carry consequences: a falsely approved loan, a missed fraud, a wrongly escalated alert each carry their own real cost.

The fix is an asymmetric loss: charge different penalties for the two error types, say $\alpha$ per false positive and $\beta$ per false negative. The total cost of a classifier on a dataset becomes $\alpha \cdot FP + \beta \cdot FN$, where $FP$ and $FN$ count each error type. The deep point: the loss is not bookkeeping, it is the channel through which you tell the model which mistakes matter. Change the penalties and the best decision threshold moves. Prove it to yourself:

Fig 3.1, the price of a threshold. Sixty screened patients, each with a real computed risk score; drag the threshold and the false positives (healthy, flagged) and false negatives (diseased, missed) are counted live. The curve underneath is the total cost $\alpha \cdot FP + \beta \cdot FN$ at every possible threshold, with the minimum marked. Slide $\beta$ up to say "a miss is ten times worse" and watch the optimal threshold walk left, flagging more people to avoid missing anyone.

Read the figure's lesson back in words. With equal penalties ($\alpha = \beta = 1$) the asymmetric cost is the zero/one count of errors, and the best threshold sits where the two classes trade off evenly. Make misses expensive and the threshold drops: the screen becomes eager, accepting many false alarms to catch nearly every true case. Make false alarms expensive and it becomes conservative. The model did not change. The data did not change. Only the statement of what we care about changed, and the right decision moved. Which raises the next question: if error counts can mislead, what numbers should we report?

4. Metrics beyond accuracy

Accuracy answers "how often are we right?". It is one number, it is easy, and under class imbalance it is a trap. Screen 100 patients of whom 10 are diseased, and the classifier that says "healthy" to everyone scores 90% accuracy while catching zero cases. The number looks great and the classifier is useless. To do better we need metrics that ask a sharper question: not how often are we wrong, but what kind of errors are we making?

Start by sorting every prediction into one of four bins. A true positive (TP) is a positive we caught, a true negative (TN) a negative we correctly cleared, and the two error types from section 3 fill the off-diagonal: false positives (FP) and false negatives (FN). Arranged as a 2×2 table, this is the confusion matrix, and every metric below is arithmetic on its four cells:

$$ R = \frac{TP}{TP + FN}, \qquad P = \frac{TP}{TP + FP}, \qquad F_1 = 2\,\frac{P \cdot R}{P + R}, \qquad \text{Acc} = \frac{TP + TN}{TP + TN + FP + FN} $$
  • Recall $R$: of all the truly positive cases, how many did we catch? Of all the fraud that happened, how much did we flag? The denominator is the truth column, so recall is blind to false alarms.
  • Precision $P$: of everything we flagged positive, how much was truly positive? The denominator is our own flag pile, so precision is blind to misses.
  • $F_1$: the harmonic mean of the two. The harmonic mean punishes imbalance, so a model cannot buy a good $F_1$ by maxing one metric and abandoning the other.
Worked by hand: one full confusion matrix

The diabetes screen from section 3, on 100 patients of whom 10 are diseased. Suppose the screen flags 15 people, and 6 of them are genuinely diseased. Fill the four cells: $TP = 6$ (diseased, flagged), $FN = 10 - 6 = 4$ (diseased, missed), $FP = 15 - 6 = 9$ (healthy, flagged), $TN = 90 - 9 = 81$ (healthy, cleared). Now the metrics, digit by digit:

$$ R = \frac{6}{6+4} = 0.60 \qquad P = \frac{6}{6+9} = \frac{6}{15} = 0.40 $$ $$ F_1 = 2 \cdot \frac{0.40 \times 0.60}{0.40 + 0.60} = 2 \cdot \frac{0.24}{1.00} = 0.48 \qquad \text{Acc} = \frac{6 + 81}{100} = 0.87 $$

Now the punchline. The lazy "everyone is healthy" classifier has $TP = 0$, $FP = 0$, $FN = 10$, $TN = 90$: accuracy $0.90$, better than our screen, with recall $0$ and precision undefined. Accuracy ranked a useless model above a useful one. Recall exposes the fraud instantly: $0.60$ versus $0$.

From the confusion matrix in code, the metrics are three lines:

def precision_recall_f1(y_pred, y_true):
    tp = np.sum((y_pred == 1) & (y_true == 1))
    fp = np.sum((y_pred == 1) & (y_true == -1))
    fn = np.sum((y_pred == -1) & (y_true == 1))
    precision = tp / (tp + fp)
    recall    = tp / (tp + fn)
    f1 = 2 * precision * recall / (precision + recall)
    return precision, recall, f1

Here is the part that makes all of this dynamic rather than static: the confusion matrix is a function of the threshold. Slide the cutoff down and you flag more people, so recall rises and precision usually falls. Slide it up and the reverse. Precision and recall are two ends of one lever. Feel the lever:

Fig 4.1, the confusion-matrix explorer, on the same 60 screened patients as Fig 3.1. Drag the threshold through the scores; every point is re-binned into TP, FP, TN, or FN on the spot, and precision, recall, $F_1$, and accuracy are recomputed from the four live counts. Push the threshold left until recall hits 1.00 and watch what happens to precision.

Every threshold position in Fig 4.1 produces one (recall, precision) pair. Sweep the threshold across its whole range, collect all the pairs, and you get the precision-recall curve: a portrait of every trade-off this scorer can offer. Each point on the curve is one threshold setting. The threshold picks where you stand on the curve, but the curve itself belongs to the model; train a better scorer (or a worse one) and the entire curve shifts. That separation is exactly what makes PR curves the right tool for comparing models before anyone has committed to a threshold:

Fig 4.2, the precision-recall curve, traced from real threshold sweeps over the Fig 4.1 data. The orange marker is the threshold you set in Fig 4.1, drag in either figure and the other follows. Toggle the weaker model, a noisier score on the same patients, and its whole curve sits lower: at any recall you want, it offers less precision.

One discipline note before the quiz, because these ideas blur together in week 10 if you let them. Keep three quantities distinct. The training loss is what the optimizer minimizes; it must be well behaved (differentiable, so far squared error, soon cross-entropy). The evaluation metric is how you judge the model on validation and test data; precision, recall, $F_1$ live here, and they need not be differentiable because nothing optimizes them directly. The deployment objective is what the organization actually cares about, dollars, missed diagnoses, user trust, and it usually is not even computable from the dataset. Good practitioners translate the third into the second and pick the first to serve it.

Check: why recall is the metric that matters for disease screening

Argue in three or four sentences why a screening program should watch recall above precision or accuracy, and name the cost of pushing recall too aggressively.

Answer. A screen exists to make sure true cases do not slip through: the catastrophic error is the false negative, a sick patient sent home, and recall is precisely the fraction of true cases caught. Accuracy is dominated by the huge healthy majority, so it barely moves when the screen misses patients, and precision only audits the people we flagged, saying nothing about the ones we failed to flag. The cost of chasing recall to 1.0 is a flood of false positives: every flagged patient consumes a follow-up test, money, and worry, which is Fig 4.1's trade in action. In practice you set a recall floor from the medical stakes, then take whatever precision the PR curve offers at that recall, and that is a decision about values, not statistics.

5. The perceptron

So far we chose weights by recycling least squares, and Fig 1.1 showed the price. Time to learn the boundary as a boundary. The algorithm that first did this is worth meeting properly, history included. In 1958 Frank Rosenblatt introduced the perceptron, a learning rule inspired by a simplified neuron: inputs arrive with weights, the sum crosses a threshold, and the unit fires or does not. The optimism around it was enormous. In 1969 Marvin Minsky and Seymour Papert's book Perceptrons proved that a single perceptron is nothing more than a linear classifier, with everything that implies, including a famous four-point dataset it can never solve. That result, and the clarity it forced about needing layers and nonlinearities, shaped the next fifty years of the field. We will hit the same wall ourselves at the end of this section.

The setup and the goal

Binary labels $t \in \{-1, +1\}$. Linear score $z = w^\top x$, where from here on we fold the intercept in: prepend a constant feature $x_0 = 1$ to every input so that $w_0$ rides along inside $w$ and the algebra stays clean. Prediction $y(x) = \operatorname{sign}(z)$, the same decision rule as before. The goal is the most literal one imaginable: choose $w$ to minimize the number of mistakes,

$$ \operatorname*{arg\,min}_w \; J_{0\text{-}1}(w) = \sum_n \mathbb{I}\!\left[ t^{(n)} \neq \operatorname{sign}\!\left(w^\top x^{(n)}\right) \right] $$

Zero/one loss has no useful gradient, so the perceptron does not descend it. It does something more direct. First, a compact test for "mistake". Multiply the score by the true label to get the signed score $t^{(n)}\, w^\top x^{(n)}$. If the prediction is right, score and label share a sign and the product is positive. If wrong, they disagree and

$$ t^{(n)} \, w^\top x^{(n)} < 0 \qquad \text{(the mistake condition)} $$

One number now encodes both correctness (its sign) and confidence (its size). The whole algorithm is: walk through the examples, and every time the signed score is negative, nudge the weights by the misclassified example itself:

$$ w_{\text{new}} = w_{\text{old}} + t^{(n)} x^{(n)} $$

If a positive point was on the wrong side, add it to $w$, pulling the normal vector toward it. If a negative point was on the wrong side, subtract it, pushing the normal away. Correct points are left completely alone. Why does the nudge help? Compute the new signed score on the offending example:

$$ t^{(n)} \, w_{\text{new}}^\top x^{(n)} = t^{(n)} \left( w_{\text{old}} + t^{(n)} x^{(n)} \right)^\top x^{(n)} = t^{(n)} \, w_{\text{old}}^\top x^{(n)} + \lVert x^{(n)} \rVert^2 $$

using $(t^{(n)})^2 = 1$. The update adds $\lVert x^{(n)} \rVert^2$, a strictly positive quantity, to the signed score. Every update pushes that example's signed score up, toward positive, toward correct. It may take several visits, and fixing one point can disturb another, but each individual correction moves in the right direction. The full algorithm:

  1. Initialize $w$ (zeros are fine).
  2. Repeat over the examples: pick $(x^{(n)}, t^{(n)})$, predict $y^{(n)} = \operatorname{sign}(w^\top x^{(n)})$. If correct, do nothing. If wrong, update $w \leftarrow w + t^{(n)} x^{(n)}$.
  3. Stop when a full pass makes no mistakes, or after a fixed number of passes.
Worked by hand: two updates to convergence

Three examples with the constant feature folded in, $\tilde{x} = (1, x_1, x_2)$: $x^{(1)} = (1, 2)$ with $t^{(1)} = -1$,  $x^{(2)} = (2, -1)$ with $t^{(2)} = +1$,  $x^{(3)} = (-1, 1)$ with $t^{(3)} = -1$. Start at $w = (0, 0, 0)$.

Visit $x^{(1)}$. Score $w^\top \tilde{x}^{(1)} = 0$, so $y = \operatorname{sign}(0) = +1 \neq -1$: mistake. Update $w \leftarrow (0,0,0) - (1, 1, 2) = (-1, -1, -2)$. Recheck the signed score: it was $0$, and now $t\, w^\top \tilde{x} = -1 \times (-1 - 1 - 4) = 6$. It rose by exactly $\lVert \tilde{x} \rVert^2 = 1 + 1 + 4 = 6$, as the algebra promised.

Visit $x^{(2)}$. Score $= -1 + (-1)(2) + (-2)(-1) = -1$, so $y = -1 \neq +1$: mistake, signed score $-1$. Update $w \leftarrow (-1,-1,-2) + (1, 2, -1) = (0, 1, -3)$. New signed score: $+1 \times (0 + 2 + 3) = 5 = -1 + 6$, up by $\lVert \tilde{x} \rVert^2 = 1 + 4 + 1 = 6$ again.

Visit $x^{(3)}$. Score $= 0 - 1 - 3 = -4$, $y = -1 = t$: correct, no update.

Pass 2. $x^{(1)}$: score $0 + 2 - 6 = -4$, correct. $x^{(2)}$: score $5$, correct. $x^{(3)}$: score $-4$, correct. A clean pass: converged after just two updates, with final $w = (0, 1, -3)$, i.e. the boundary $x_1 - 3 x_2 = 0$.

Convergence, and the wall

Call a dataset linearly separable if some straight boundary classifies every example correctly. The perceptron's guarantee, proved by Novikoff in 1962, is clean: if the data is linearly separable, the perceptron converges, reaching a boundary with zero mistakes in a finite number of updates. No learning rate to tune, no local minima. But the guarantee's hypothesis carries all the weight. If the data is not linearly separable, the perceptron may update forever, cycling through weight vectors, because there is always some mistake left to trigger another nudge.

And non-separable data does not need to be exotic. Minsky and Papert's counterexample is four points. Take two binary inputs and label them by XOR, "exclusive or": the label is positive when exactly one input is 1. The two positive points sit on one diagonal, the two negative points on the other. A single perceptron can represent AND and OR without trouble, but no line in the plane puts both diagonals on opposite sides. Try it yourself, seriously, try:

Fig 5.2, the XOR wall. Drag the line's two handles and try to separate the four points; the correct count is computed live, and for XOR it never reaches 4 of 4. Switch the gate to AND or OR and the same line succeeds easily. Then press "let the perceptron try": on AND and OR it converges, on XOR it thrashes forever, capped here at 60 updates for mercy.

The XOR wall is a limit on the representation, not on the learning rule. The perceptron finds a separating line whenever one exists; XOR is a world where none exists in the raw features. The escape routes define the rest of the course: map the inputs into a feature space where the classes do separate (the end quiz has you build exactly this for XOR), or stack perceptron-like units into layers, which is the founding idea of neural networks. Either way, the takeaway stands: the perceptron is the simplest story of learning a decision boundary by repeated correction, and its failure told the field what to build next.

6. Multi-class classification

Everything so far was two classes. Real problems often have $K > 2$: digit recognition has ten classes, a triage system has several severity levels. Some models we already know extend to $K$ classes without any surgery. Multi-class k-NN just reports the most common class among the $k$ neighbours; a vote never cared how many parties there were. Multi-class decision trees are equally untroubled: impurity counts all $K$ classes and a leaf predicts its most frequent one. Linear classifiers need more thought, because a single score line only splits the world in two. There are two families of strategies: build one model that emits $K$ scores, or combine many binary classifiers.

Direct: one-hot least squares

Encode each label as a one-hot vector, length $K$ with a single 1 in the class's slot. Fit one linear scoring function per class by least squares, exactly the section 1 trick run $K$ times:

$$ y_k(x) = w_k^\top x + b_k, \qquad \hat{y}(x) = \operatorname*{arg\,max}_k \; y_k(x) $$

At prediction time, every class announces a score and the largest one wins. This is a fine baseline and it inherits least squares' speed, but a caution from the source material worth keeping verbatim in spirit: the $K$ scores are not calibrated probabilities. They can be negative, they do not sum to one, and their absolute sizes mean nothing; only the argmax is trustworthy.

Reductions: one-vs-rest and one-vs-one

One-vs-rest (OvR) trains $K$ binary classifiers, the $k$-th separating class $k$ from everything else, and predicts the class whose classifier shouts loudest. The failure mode is baked in: on a given input, several classifiers may say "yes, mine" or none may. Then you need a tie-break rule, and comparing raw scores across independently trained classifiers is dubious, because each was trained on a different problem and their scales need not agree.

One-vs-one (OvO) trains a classifier for every pair of classes, $\binom{K}{2} = K(K-1)/2$ of them; each pairwise classifier votes for one of its two classes, and the most-voted class wins. Each binary problem is small and clean, but the cost grows quadratically in $K$ (for $K = 10$ that is already 45 classifiers), and the votes can do something genuinely strange: pairwise preferences can cycle, $C_1 \succ C_2$, $C_2 \succ C_3$, $C_3 \succ C_1$, a three-way tie with no majority winner, just like a rock-paper-scissors election.

Fig 6.1, three strategies, one dataset. Toggle between one-hot least squares (argmax of three real fitted scores), one-vs-rest, and one-vs-one; the coloured regions are recomputed from the actual trained classifiers. Drag the query point and the readout shows its three scores or its three pairwise votes and how the winner is chosen. In the OvR and OvO views, the washed-out zones are the conflicts: regions where no classifier claims the point, several do, or the vote ties.

The honest summary: multi-class is not just binary repeated. Every strategy above works, and every one of them owes you a definition of how scores, votes, or conflicts get resolved. When a library hands you a multi-class linear classifier, one of these three stories (usually OvR or a softmax generalization you will meet soon) is running underneath.

Check your understanding

A one-vs-one system over classes $\{1, 2, 3\}$ reports: the (1 vs 2) classifier picks 1, the (1 vs 3) classifier picks 3, and the (2 vs 3) classifier picks 2. What does the system predict?

Matchup order carries no authority; OvO aggregates by vote count, and the counts here are 1, 1, 1.
That chain reasoning assumes preferences are transitive, and this example is precisely the proof that pairwise winners need not be: 1 beats 2, 2 beats 3, and yet 3 beats 1.
Right. The tally is 1-1-1, a cycle, and OvO has no internal answer. Implementations fall back to score magnitudes, class priors, or arbitrary order, and you can summon this exact situation in Fig 6.1 by parking the query in the grey central zone of the OvO view.
Check: one-vs-rest says yes twice. Now what?

An OvR system over three classes evaluates a query and gets scores $y_1 = +0.8$, $y_2 = +0.3$, $y_3 = -0.5$. Two classifiers claim the point. What is predicted, and what is the caveat?

Answer. The standard rule is argmax: predict class 1, since $0.8$ is the largest score. The caveat is that this comparison is not really licensed. Classifier 1 was trained on "class 1 vs rest" and classifier 2 on "class 2 vs rest", two different problems with independently scaled scores; $0.8$ from one is not necessarily more confident than $0.3$ from the other. Argmax is a pragmatic tie-break, not a principled probability comparison, which is one motivation for the calibrated, softmax-based multi-class models coming later in the course. The same applies when every score is negative: nobody says yes, and argmax quietly picks the least emphatic no.

7. Summary and method card

The whole lecture compresses into one sentence: compute a linear score, threshold it, and take the consequences seriously. The score is regression's $w_0 + w^\top x$, unchanged. The threshold creates a decision boundary, a point, line, or plane, whose normal vector is $w$. The consequences are where all the substance lives: errors split into false positives and false negatives with genuinely different costs, accuracy stops being a trustworthy summary the moment classes are imbalanced, and precision, recall, and the PR curve report what kind of mistakes a threshold buys you. The perceptron learns the boundary by the simplest correction rule imaginable, adding misclassified examples into the weights, and it provably converges exactly when a separating line exists. XOR shows how easily one fails to exist. And multi-class turns out to be a design problem, argmax scores, one-vs-rest, one-vs-one, each with a conflict mode you must resolve by explicit rule.

Method card · Linear Classification
AssumptionA linear score suffices to separate the classes in the chosen feature space.
Model classScore $s(x) = w_0 + w^\top x$, then threshold to a label; the threshold defines the boundary $w_0 + w^\top x = 0$.
Learning / selectionChoose weights, intercept, threshold, loss, and evaluation metric to fit the task. The perceptron updates $w \leftarrow w + t\,x$ only on misclassified examples.
Prediction$y(x) = \operatorname{sign}(w_0 + w^\top x)$; multi-class via argmax of $K$ scores, one-vs-rest, or one-vs-one.
StrengthsSimple, efficient, interpretable (per-feature contributions $w_i x_i$), with a clear geometric picture.
LimitationsOnly linear boundaries (XOR is unsolvable); hard thresholds are not differentiable and are threshold-sensitive; the perceptron converges only on linearly separable data.
Next stepReplace the hard threshold with a differentiable probabilistic model (logistic regression), then nonlinear feature maps, kernels, and neural networks.

Where this sits in the course story: similarity (kNN), rules (trees), parametric functions (linear regression), and now decisions. The two sharpest complaints from today, that hard thresholds kill gradients and that scores are not probabilities, are both answered by one idea: replace the cliff of $\operatorname{sign}$ with a smooth ramp that outputs the probability of the positive class. That is the sigmoid, that is logistic regression, and that is next lecture.

8. End-of-lesson quiz

Two quick checks, then three transfer questions that ask you to design, not recall. Attempt each before expanding the answer.

Quiz 1

A rare-disease detector reports 99.0% accuracy on a test set where 1% of patients are diseased. Your supervisor is impressed. Should you be?

Compute the baseline first. Predicting "healthy" for everyone is right 99% of the time here, while catching zero patients. Matching a useless model is not excellence.
Right. Under 1% prevalence, accuracy is dominated by the easy negatives. The detector could have recall 0 or recall 0.9 and show the same 99.0%; only error-type-aware metrics can tell those two systems apart, which is the entire argument of section 4.
High accuracy is not evidence of overfitting by itself; that diagnosis needs a train-test gap. The issue here is imbalance making the metric hollow, not memorization.
Quiz 2

During a perceptron run, example $x = (1, 2, -1)$ (bias folded in) with $t = +1$ has signed score $t\,w^\top x = -2$. The update fires. What is the signed score of this same example immediately after?

Right. $t\,(w + t x)^\top x = t\,w^\top x + t^2 \lVert x \rVert^2 = -2 + (1 + 4 + 1) = 4$. This example lands on the correct side in one step, though a larger initial deficit could need several visits.
The update does not aim for the boundary; it adds the fixed amount $\lVert x \rVert^2 = 6$ to the signed score, wherever that lands it.
The beauty of the algebra is that $w$ cancels: the change in signed score is $\lVert x \rVert^2$ regardless of the current weights.
Quiz 3 (transfer): design an asymmetric loss and defend the numbers

Pick an application you know (airport security screening, spam filtering, a smoke detector, code review bots). Assign penalties $\alpha$ (false positive) and $\beta$ (false negative), justify the ratio, and predict how the ratio moves the operating threshold.

Answer (one honest version, smoke detector). A false positive is an alarm during cooking: cost is annoyance and a minute of waving a towel, call it $\alpha = 1$. A false negative is an undetected fire: property and possibly lives, conservatively thousands of times worse, so $\beta = 5000$. With $\beta/\alpha$ that extreme, the cost-minimizing threshold in the Fig 3.1 sense sits far into the cautious side: the detector should fire on weak evidence, accepting frequent false alarms, because one miss outweighs thousands of them. That matches how real detectors behave. The reasoning template for any domain: price both errors in comparable units (money, time, harm), take the ratio, and remember the threshold implements values, so different stakeholders (the person cooking vs the fire marshal) may legitimately want different thresholds on the same model. Spam is the mirror case: a lost job offer (false positive) dwarfs one more spam email (false negative), so $\alpha \gg \beta$ and the filter should hesitate to flag.

Quiz 4 (transfer): make a linear classifier solve XOR

No line in $(x_1, x_2)$ separates XOR. Propose a feature map that fixes this, give explicit weights that classify all four points correctly, and verify one point by hand.

Answer. Add the product feature: map $(x_1, x_2) \mapsto (x_1, x_2, x_1 x_2)$. The new coordinate is 1 only for $(1,1)$ and 0 for the other three points, which breaks the diagonal symmetry that made XOR impossible. Explicit weights: $s(x) = -0.5 + x_1 + x_2 - 2\,x_1 x_2$. Check all four: $(0,0)$: $s = -0.5 < 0$, predict $-1$ ✓. $(1,0)$: $s = -0.5 + 1 = 0.5 \ge 0$, $+1$ ✓. $(0,1)$: $s = 0.5$, $+1$ ✓. $(1,1)$: $s = -0.5 + 1 + 1 - 2 = -0.5 < 0$, $-1$ ✓. The model is still linear in its features; the features stopped being raw inputs. This is the whole idea behind basis functions and kernels, and a two-layer network learns such a map instead of hand-designing it, which is precisely the response to Minsky and Papert's critique.

Quiz 5 (transfer): when does a PR curve beat a single accuracy number?

Your team must choose between two fraud models. Argue when a precision-recall curve is the right comparison tool and a single accuracy number is not, and name one situation where accuracy alone is fine.

Answer. Reach for the PR curve when three conditions stack up, and fraud has all three. First, class imbalance: fraud is rare, so accuracy is propped up by the easy negatives and can rank a useless model above a useful one, as in the section 4 worked example. Second, asymmetric costs: missed fraud and blocked legitimate purchases hurt differently, so you care about the error types separately, which is exactly what the curve's two axes report. Third, an unfixed threshold: the deployment team will tune the cutoff later, so you should compare models across all thresholds at once; one model's curve sitting above another's (as in Fig 4.2) means it wins at every operating point, a conclusion no single-threshold number can deliver. Accuracy alone is fine when classes are roughly balanced, both error types cost about the same, and the threshold is fixed, a coin-sorting machine, say, or a balanced benchmark dataset used only for a quick sanity check.

That is linear classification: one linear score, one threshold, and every consequence taken seriously, boundaries and half-spaces, false positives against false negatives, precision against recall, a learning rule that repairs one mistake at a time, and a four-point dataset that humbled a field. The machinery that fixes its sharpest flaw, a hard cliff where a gradient should be, is one smooth curve away. Next lecture: logistic regression.
